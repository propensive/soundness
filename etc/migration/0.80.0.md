# Changes since 0.79.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.79.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## cataclysm

- The `css"…"` interpolator now validates the literal declarations it contains at compiletime,
  as `text.read[Css]` validates them at runtime. A declaration of an unknown property
  (`css"a { colour: red }"`), a value its property's grammar rejects (`css"a { width: wide }"`),
  or a value which uses a grammar type the matcher does not implement, is a compile error; each
  previously compiled and produced the `Css` or `Css.Style` unchecked. Correct the property or
  the value. A custom property (`--name`) still takes any value, and a value which contains
  `var(…)` or `env(…)` is accepted. A declaration with a substitution (`css"a { color: $red }"`)
  is checked as before, against the type of the value substituted.
- Declarations in the block of an at-rule which holds descriptors, not properties, are no
  longer validated as properties, by `text.read[Css]` or by `css"…"`. Every at-rule is such a
  rule except `@media`, `@supports`, `@layer`, `@container`, `@scope`, `@starting-style`,
  `@document` and `@position-try`. `t"@font-face { src: url(x) }".read[Css]` raised a
  `Css.Errors` holding `Css.Error.Reason.UnknownProperty(t"src")`, and now succeeds.
- A declaration in the block of `@font-face`, `@counter-style`, `@font-palette-values`,
  `@property` or `@view-transition` is validated against the descriptors of that at-rule. One
  which is not a descriptor of it raises the new case
  `cataclysm.Css.Error.Reason.UnknownDescriptor(rule: Text, name: Text)` (number 10), where
  `rule` is the at-rule's name without its `@`; a `match` which names every case of
  `Css.Error.Reason` must name it. A descriptor whose value its grammar rejects raises
  `BadValue`. So `t"@font-face { color: red }".read[Css]`, which succeeded because `color` is a
  property, now raises `UnknownDescriptor(t"font-face", t"color")`. A declaration in the block
  of `@page` is validated as a descriptor of `@page` if it is one, and as a property otherwise.
  The block of any other at-rule which is not in the list above is not validated.
- `object cataclysm.PropertyDef` gains `descriptors: Dictionary[PropertyDef]`, keyed as
  `rule/descriptor` (`font-face/src`), `descriptor(rule: Text, name: Text):
  Optional[PropertyDef]` and `descriptive(rule: Text): Boolean`.
- A `cataclysm.Css.Error` whose `reason` is `UnknownProperty`, `BadValue` or `UnsupportedValue`
  now has the `line` and `column` of the first character of its declaration (the start of the
  property's name). They were those of the character which ends the declaration: its `;`, the
  `}` which closes its block, or the end of the input.

## coaxial

- The extension `duplex` on an endpoint, and the given `coaxial.connectableSessional`, take
  their `Connectable` instance as a `using` parameter with a capture set of its own (`[…,
  instance^]`, `(using connectable: (endpoint is Connectable)^{instance})`); it was a context
  bound on the endpoint's type. A call which leaves the instance to be inferred is unchanged,
  and `(ip"…" on Port[Tcp](…)).session` and `.duplex` now compile under capture checking. A
  call which passed the `Connectable` explicitly, as the first of the context-bound arguments,
  passes it in the new `using` clause instead. (#2568)

## contingency

- The context parameters of `safely`'s block are named `diagnostics`, `tactic` and `canThrow`.
  No call changes; a capture-checking error about a value which leaves `safely` names `tactic`.
  (#2568)

## enigmatic

- New type `enigmatic.Cloaked[secret <: AnyRef, cloak^]`, an alias of `secret { val secret:
  Secret^{cloak} }^{cloak}`. It is the result type of `Password.apply` (both overloads),
  `PrivateKey.generate`, `SymmetricKey.generate` and `SymmetricKey.apply` (both overloads), which
  returned `Password^{cloak}`, `PrivateKey[cipher]^{cloak}` and `SymmetricKey[cipher]^{cloak}`.
  Every `Cloaked[key, {cloak}]` conforms to `key^{cloak}`, so code which ascribes or passes the
  old types is unchanged. A `val` which is a member of an object or a class and is initialized
  from one of these no longer needs an explicit type under capture checking. (#2568)
- `class SymmetricKey[cipher <: Cipher]`'s constructor parameter is named `secret` (was
  `handle`), and overrides `PrivateKey`'s field of that name. `new SymmetricKey(handle = …)`
  becomes `new SymmetricKey(secret = …)`; the `SymmetricKey(…)` and `SymmetricKey.generate`
  factories are unchanged. (#2568)
- The context parameters of the blocks of `Password#uncloak`, `PublicKey#uncloak`,
  `PrivateKey#uncloak` and `SymmetricKey#uncloak` are named `cleartext`, `encryptor` and
  `decryptor`. No call changes. (#2568)

## galilei

- The extension `stream` on a file handle (`(Handle & Granting[Grant.Read])^`) returns
  `(Stream[Data] over Credit)^`, the handle's own stream, which is a capability and cannot be
  the result of the `open` block; it returned a lazy `Chain[Data]`, which could, and was then
  read after the file had closed. Code which consumed the chain within the block keeps
  working where the operation exists on a stream (`handle.stream.read[Text]`,
  `handle.stream.memoize`, `handle.stream.decompress[Gzip]`). Code which returned
  `handle.stream` from the block, or bound it as a `Chain[Data]`, must read what it needs
  inside the block: `path.open[File]()(file.read[Data])`. (#2568)
- `read` on a file handle is a member of `galilei.Handle`, `def read[result](using readable:
  (Chain[Data] is Readable to result)^, tactic: Tactic[Truncation.Error], grant: this.type <:<
  (Granting[Grant.Read]^)): result`; it was an extension in `Handle`'s companion. A call
  `handle.read[Text]` is written as before, and now compiles under capture checking in code
  which imports `soundness.*` (it was rejected, the generic `read` being chosen ahead of the
  extension). A class which extends `Handle` and defines its own member named `read` must
  rename it. (#2568)

## guillotine

- `sh"…"` tokenizes its literal as the code compiles and constructs the `Command`; it emitted
  calls to `Sh.Runtime.parse`, `insert` and `complete`, which tokenized it each time it ran.
  The command made is the same. `Sh.Runtime` gains `quoted`, `word` and `command`, which the
  literal's code calls; `parse`, `insert`, `skip`, `initial` and `complete` remain. (#2571)

## honeycomb

- A value which is HTML, substituted as a child in an `h"…"` literal (`h"<ul>$item</ul>"`), is
  put in as the nodes it is; it was shown as text, and that text became a single text node. A
  fragment gives each of its nodes. Where the value's type says which elements it may be
  (`Html of "p"`), each must be an element the parent admits, or the literal does not compile:
  `<p> cannot be a child of <ul>`. Code which relied on the text must show the value itself,
  `h"<ul>${item.show}</ul>"`. (#2576)
- An `h"…"` literal with an attribute written in full (`h"""<input alt="title">"""`) compiles
  under capture checking; it failed with a type mismatch. No source changes. (#2574)
- The message for a substituted attribute value of the wrong type is `<a type> cannot be the
  value of the attribute <name>, which takes <a kind>`; it was `<type> cannot be attributed to an
  attribute of <the compiler's form of the type>`. The message for a substitution which cannot
  be shown is `<a type> cannot be shown as text, so it cannot be substituted here`; it was `a
  <type> is Showable is required`. `x"…"` has the same two. A test which matches the old text
  must match the new. (#2578)

## jacinta

- A parse error in a `j"…"` literal is marked at the character where the parser stopped; it
  was marked at the first character of the literal. The message is unchanged. (#2571)
- `j"null"` compiles, as a literal and as a pattern, and so does a `null` within a larger
  literal; each failed with `unexpected JSON AST node JsonNull`. (#2575)

## parasite

- The context parameter of `supervise`'s block is named `monitor`. No call changes; a
  capture-checking error about a task which leaves `supervise` names `monitor`. (#2568)

## proscenium

- `proscenium.TrieMap` and `soundness.TrieMap` are a type alias, `type TrieMap[key, value] =
  scala.collection.concurrent.TrieMap[key, value]`, and an inline method which gives the
  companion; they were an `export` of `scala.collection.concurrent.TrieMap`. `TrieMap()`,
  `TrieMap.empty` and `TrieMap[key, value]` as a type are written as before. Code which names
  the companion as a stable path (`import TrieMap.*`, `TrieMap.type`) must name
  `scala.collection.concurrent.TrieMap` instead. (#2568)

## revolution

- A `v"…"` literal which is not a valid version is reported with the decoder's reason and its
  code, as `[↯/s.97.1.N] the version is not valid: <reason>`, at the place in the literal where
  the reason applies; it was `invalid semantic version`, for the whole literal. A test which
  matches the old message must match the new. A valid literal is unchanged. (#2571)

## toolchain

- Soundness is compiled with Proscala 1.2.1 on Scala's `main` line, as
  `3.11.0-54094c068ffa2602-pro-1.2.1`; it was `3.10.0-pro-1.2.0`. A project which compiles
  against Soundness uses the same compiler: set its Scala version to
  `3.11.0-54094c068ffa2602-pro-1.2.1`. Capture and separation checking are stricter from Scala
  3.10.2: a method which returns one of its instance's arrays must say so (`Array[Byte]^{this.rd}`,
  not a bare `Array[Byte]`), and a method which hands on or assigns a `var` field holding an
  exclusive value must be an `update def`. (#2568)

## turbulence

- New extension `read[result]` on `(Stream[Data] over Credit)^`, which consumes the stream:
  `def read[result](using readable: (Chain[Data] is Readable to result)^, buffering:
  Buffering): result`. A stream of bytes is now read with `stream.read[Text]` or
  `stream.read[Data]`, as a `Streamable` value is. (#2568)

## urticose

- `url"…"` parses its literal as the code compiles and constructs the `Url`; it emitted code
  which joined the text and parsed it each time it ran. Four things can be observed:
  - A substituted `Int` which is not the port, after the colon of the authority, is a compile
    error: `url"https://example.com/acts/$act"` does not compile. It compiled, and threw
    `UrlInterpolatorError` when the code ran. Show the number as text (`${act.show}`), or give
    its type an instance of `contextual.Embeddable by Url.Fragment`, which is then used wherever
    the number is not a port.
  - A substitution in the scheme (`url"$scheme://example.com/"`) is a compile error.
  - A literal which is not a valid URL is reported as `[↯/s.100.8.N] the URL is not valid:
    <reason>`, at the character at fault; it was `the URL <text> is not valid: <reason> at
    <offset>`, for the whole literal.
  - `urticose.protointernal.Runtime` no longer has `initial`, `parse`, `skip`, `substitute`,
    `insert` and `complete`; it has `text`, `host`, `ipv6` and `port`. Nothing but the code of a
    `url"…"` literal should have called them. (#2571)

## xylophone

- An `x"…"` pattern which names an attribute no longer throws `NoSuchElementException` when the
  value matched has no such attribute: it does not match, and the next case is tried. This
  holds for a literal value (`x"""<a id="5">$child</a>"""`) and for one which is extracted
  (`x"<a id=$value>$child</a>"`). (#2572)

## zephyrine

- `Cursor#grab(start, end)` and `Cursor#cue(mark)` take a second clause, `(using held:
  Cursor.Held)`, as `Cursor#mark` does. Inside `cursor.hold: …` or `cursor.lookahead: …` the
  token is in scope and calls are unchanged. A call outside both no longer compiles: move it
  into the `hold` which took the marks. A parser which keeps its marks across methods, under a
  hold it manages itself, passes the token it holds, or `Cursor.shared`, explicitly:
  `cursor.cue(mark)(using Cursor.shared)`. (#2568)
- `zephyrine.Producer.Lending[medium]` is `(region: Region[medium]^) => (Interval in
  region.type) ->{caps.any, region} Unit`; it was `(region: Region[medium]) => (Interval in
  region.type) => Unit`. The region lent by `Json.lend`, `Tel.lend`, `Xml.lend`,
  `Producer.lendUtf8` and `Producer.Utf8Writer.lend` is therefore a capability under capture
  checking: a consumer which stored the region, or a closure over it, in a variable outside
  the call no longer compiles, and must copy what it keeps with `region.materialize(interval)`.
  A consumer which only reads the region within the call is unchanged. (#2568)
