# Changes since 0.79.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.79.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## coaxial

- The extension `duplex` on an endpoint, and the given `coaxial.connectableSessional`, take
  their `Connectable` instance as a `using` parameter with a capture set of its own (`[…,
  instance^]`, `(using connectable: (endpoint is Connectable)^{instance})`); it was a context
  bound on the endpoint's type. A call which leaves the instance to be inferred is unchanged,
  and `(ip"…" on Port[Tcp](…)).session` and `.duplex` now compile under capture checking. A
  call which passed the `Connectable` explicitly, as the first of the context-bound arguments,
  passes it in the new `using` clause instead. (#2565)

## contingency

- The context parameters of `safely`'s block are named `diagnostics`, `tactic` and `canThrow`.
  No call changes; a capture-checking error about a value which leaves `safely` names `tactic`.
  (#2565)

## enigmatic

- New type `enigmatic.Cloaked[secret <: AnyRef, cloak^]`, an alias of `secret { val secret:
  Secret^{cloak} }^{cloak}`. It is the result type of `Password.apply` (both overloads),
  `PrivateKey.generate`, `SymmetricKey.generate` and `SymmetricKey.apply` (both overloads), which
  returned `Password^{cloak}`, `PrivateKey[cipher]^{cloak}` and `SymmetricKey[cipher]^{cloak}`.
  Every `Cloaked[key, {cloak}]` conforms to `key^{cloak}`, so code which ascribes or passes the
  old types is unchanged. A `val` which is a member of an object or a class and is initialized
  from one of these no longer needs an explicit type under capture checking. (#2565)
- `class SymmetricKey[cipher <: Cipher]`'s constructor parameter is named `secret` (was
  `handle`), and overrides `PrivateKey`'s field of that name. `new SymmetricKey(handle = …)`
  becomes `new SymmetricKey(secret = …)`; the `SymmetricKey(…)` and `SymmetricKey.generate`
  factories are unchanged. (#2565)
- The context parameters of the blocks of `Password#uncloak`, `PublicKey#uncloak`,
  `PrivateKey#uncloak` and `SymmetricKey#uncloak` are named `cleartext`, `encryptor` and
  `decryptor`. No call changes. (#2565)

## galilei

- The extension `stream` on a file handle (`(Handle & Granting[Grant.Read])^`) returns
  `(Stream[Data] over Credit)^`, the handle's own stream, which is a capability and cannot be
  the result of the `open` block; it returned a lazy `Chain[Data]`, which could, and was then
  read after the file had closed. Code which consumed the chain within the block keeps
  working where the operation exists on a stream (`handle.stream.read[Text]`,
  `handle.stream.memoize`, `handle.stream.decompress[Gzip]`). Code which returned
  `handle.stream` from the block, or bound it as a `Chain[Data]`, must read what it needs
  inside the block: `path.open[File]()(file.read[Data])`. (#2565)
- `read` on a file handle is a member of `galilei.Handle`, `def read[result](using readable:
  (Chain[Data] is Readable to result)^, tactic: Tactic[Truncation.Error], grant: this.type <:<
  (Granting[Grant.Read]^)): result`; it was an extension in `Handle`'s companion. A call
  `handle.read[Text]` is written as before, and now compiles under capture checking in code
  which imports `soundness.*` (it was rejected, the generic `read` being chosen ahead of the
  extension). A class which extends `Handle` and defines its own member named `read` must
  rename it. (#2565)

## parasite

- The context parameter of `supervise`'s block is named `monitor`. No call changes; a
  capture-checking error about a task which leaves `supervise` names `monitor`. (#2565)

## turbulence

- New extension `read[result]` on `(Stream[Data] over Credit)^`, which consumes the stream:
  `def read[result](using readable: (Chain[Data] is Readable to result)^, buffering:
  Buffering): result`. A stream of bytes is now read with `stream.read[Text]` or
  `stream.read[Data]`, as a `Streamable` value is. (#2565)

## zephyrine

- `Cursor#grab(start, end)` and `Cursor#cue(mark)` take a second clause, `(using held:
  Cursor.Held)`, as `Cursor#mark` does. Inside `cursor.hold: …` or `cursor.lookahead: …` the
  token is in scope and calls are unchanged. A call outside both no longer compiles: move it
  into the `hold` which took the marks. A parser which keeps its marks across methods, under a
  hold it manages itself, passes the token it holds, or `Cursor.shared`, explicitly:
  `cursor.cue(mark)(using Cursor.shared)`. (#2565)
- `zephyrine.Producer.Lending[medium]` is `(region: Region[medium]^) => (Interval in
  region.type) ->{caps.any, region} Unit`; it was `(region: Region[medium]) => (Interval in
  region.type) => Unit`. The region lent by `Json.lend`, `Tel.lend`, `Xml.lend`,
  `Producer.lendUtf8` and `Producer.Utf8Writer.lend` is therefore a capability under capture
  checking: a consumer which stored the region, or a closure over it, in a variable outside
  the call no longer compiles, and must copy what it keeps with `region.materialize(interval)`.
  A consumer which only reads the region within the call is unchanged. (#2565)
