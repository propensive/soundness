# `SN-563` — `XPath.Error`

Raised when an XPath expression that parsed cannot be evaluated.

## Cause

Parsing an XPath establishes only that it is well-formed. Evaluation can
still fail: the expression may name a function that XPath 1.0 does not
define, apply one to the wrong number of arguments, reference an unbound
variable, or produce a value where a node-set was required.

This is deliberately distinct from `SN-594` (`Parse.Error` over the `XPath`
format), which reports an expression that is not well-formed at all.

## Variants

### `SN-563.1` — `UnknownFunction`

**Example.** `[↯SN-563.1] the XPath could not be evaluated because the function foo is not an XPath 1.0 core function`

**Resolution.** Use one of the core functions defined by XPath 1.0 §4.

### `SN-563.2` — `BadArity`

The function exists but was applied to the wrong number of arguments.

### `SN-563.3` — `UnboundVariable`

A `$name` reference has no binding in the evaluation context.

### `SN-563.4` — `NotNodeSet`

The expression produced a string, number or boolean where a node-set was
required — for example as the operand of a path step.

### `SN-563.5` — `Unsupported`

The expression uses a feature this implementation does not provide.

### `SN-563.6` — `Unresolved`

An interpolated `xp"…"` substitution was never resolved.
