# `SN-610` — `Telp.Error`

Raised when a TELP does not parse or does not resolve.

## Cause

TELP is TEL's textual path language over the semantic model of a schema-typed document. Its
failures are outcomes of the resolving API, not document errors: they carry no TEL E-codes.
Every reason carries the 0-based index of the component at which parsing or resolution failed.

## Variants

| Code | Reason | Message |
| --- | --- | --- |
| `SN-610.1` | `Syntax` | the path is not syntactically valid |
| `SN-610.2` | `UnknownKeyword` | the component matches no keyword of the current struct |
| `SN-610.3` | `NonStructDescent` | the path descends below a value or flag |
| `SN-610.4` | `AbsentMember` | the non-repeatable optional member is not present |
| `SN-610.5` | `IndexOutOfRange` | the index selector exceeds the occurrence sequence |
| `SN-610.6` | `TypeNotKeyed` | a key selector was applied to a type with no key field |
| `SN-610.7` | `KeyNotFound` | no occurrence has the selected key value |

## Resolution

A path's delimiter is its first character: a component containing the chosen delimiter is
written under a different one (there is no escape syntax). An all-digit component is always an
occurrence index, so an all-digit key value can only be selected by position. Resolution needs
a composed schema; an untyped document has no semantic model and no TELP resolution.
