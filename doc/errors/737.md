# `SN-737` — `Shrink.Error`

Raised when a classpath cannot be shrunk to the closed world its entry points reach.

## Cause

Shrinking recompiles the classes of a classpath from their TASTy, without the members nothing
reaches, and then follows the references of the bytecode which results to decide which other
classes go with them. This error covers a closed world which would not be sound, and the
shrinker terminating abnormally.

## Variants

### `SN-737.1` — `Unsound`

**Example.** `[↯SN-737.1] the classpath could not be shrunk because a problem was found: example.Main refers to render()Ljava/lang/String; of example.Page, which was removed`

Something which was kept refers to something which was not. The reason carries every such
reference, as `problems`: each was found either in the compiler's trees, before any bytecode
was generated, or in the bytecode afterwards. It also covers a unit which could not be
recompiled and could not be pinned in its place, with the compiler's own errors as the
problems.

**Resolution.** A reference which only reflection makes is not one the analysis can find: keep
the class it reaches, with `Shrink`'s `keep` or `shrinkOptions.keep`. A reference the analysis
should have found is a fault in it; pinning the unit which makes the reference, with `pin` or
`shrinkOptions.pin`, copies that unit as it was, and keeps everything it refers to.

### `SN-737.2` — `Failed`

**Example.** `[↯SN-737.2] the classpath could not be shrunk because the shrinker terminated abnormally`

The reason carries the stack trace.
