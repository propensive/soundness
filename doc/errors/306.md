# `SN-306` — `Rig.Error`

Raised when Superlunary cannot move a value across the boundary into or
out of a `Rig` — the classloader in which staged code is compiled and run.

This is a failure of *marshalling*, not of the staged code itself: the
value could not be written into the rig's `Transport` (`Json` or `Pojo`),
or could not be read back out of it. A failure to compile the staged tree
is `Compiler.Error`, which `Rig.dispatch` declares alongside this one.

## Cause

Superlunary marshals a call to a remote process and reads the result
back. Any failure in serialising the call, deserialising the result,
or otherwise transporting it produces this error. The message is
`failed to perform a remote operation because $reason`.

## Variants

### `SN-306.1` — `Serialization`

The output (the call or its arguments) could not be serialised for
transmission.

**Example.** `[↯SN-306.1] failed to perform a remote operation because the output could not be serialized`

**Resolution.** Confirm that all argument types have the necessary
encoders/decoders in scope and produce well-formed bytes.

### `SN-306.2` — `Deserialization`

The response from the remote could not be deserialised.

**Example.** `[↯SN-306.2] failed to perform a remote operation because the input could not be deserialized`

**Resolution.** Verify the remote is producing the expected payload
shape; mismatched schemas between client and server are the typical
cause.

### `SN-306.3` — `Unknown`

The cause does not match either of the more specific variants.

**Example.** `[↯SN-306.3] failed to perform a remote operation because of an unknown reason`

**Resolution.** Inspect logs and any cause chain.
