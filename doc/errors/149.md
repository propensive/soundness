# `SN-149` — `Xml.Error`

Raised when Xylophone cannot read a value from XML.

## Cause

This is the *decoding* error: the document parsed, but a value could not be
read out of it. A document that is not well-formed XML at all is a
`Parse.Error` (`SN-594`) over the `Xml` format, and a failure to evaluate an
XPath is `SN-563`.

These errors are raised *and continue*: a record with several bad fields
accrues one error per field rather than stopping at the first. The reason
says what went wrong; the ambient `Foci[Xml.Focus]` says where.

## Variants

### `SN-149.1` — `Malformed`

The element had text, but it did not represent a value of the expected type.

**Example.** `[↯SN-149.1] the XML could not be read because the text abc is not a valid Int`

**Resolution.** Correct the content, or read the field at a type that admits it.

### `SN-149.2` — `Untextual`

The element was present but carried no text to read at the expected type.

**Example.** `[↯SN-149.2] the XML could not be read because the element has no text to read as Int`

### `SN-149.3` — `Absent`

No element or attribute supplied a required value of a known type.

### `SN-149.4` — `AbsentProduct`

A required nested record had no element, and no `Default` was in scope.

**Resolution.** Supply the element, or give the type a `Default`.

### `SN-149.5` — `AbsentVariant`

A required sum type had no element, and no `Default` was in scope.

### `SN-149.6` — `UnknownVariant`

The discriminant attribute named no variant of the sum being read.

**Example.** `[↯SN-149.6] the XML could not be read because circle does not name a variant of Shape`

**Resolution.** Use one of the sum's variant names, or relabel the variant.

### `SN-149.7` — `Empty`

An element carried no text, read through a generic text codec that does not
name its target type.

### `SN-149.8` — `Missing`

An element or attribute was not present, read through a codec that does not
name its target type.
