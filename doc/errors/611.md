# `SN-611` — `Tels.Resolution.Error`

Raised when a TEL document's schema identification does not resolve to a schema.

## Cause

Schema resolution (TEL §8.2) turns the pragma's identification — a LIRA reference, layer
selections, and/or a BASE-256 signature — into a composed schema, through the embedded,
built-in, store, library and LIRA steps. Its failures are runtime resolution errors, outside
the document's E1xx–E3xx taxonomy (the one exception is E124, out-of-order layer selections,
which is a `Tel.Error` raised during resolution because it needs the schema's declaration
order).

## Variants

| Code | Reason | Message |
| --- | --- | --- |
| `SN-611.1` | `UnknownLayer` | the selected layer is not declared by the schema |
| `SN-611.2` | `ComponentCount` | the signature has the wrong number of components |
| `SN-611.3` | `BaseMismatch` | the signature's base component does not match the schema's base hash |
| `SN-611.4` | `LayerMismatch` | the signature's component for a layer does not match its hash |
| `SN-611.5` | `ReferenceDisagrees` | the reference's lineage does not serve the authoritative signature |
| `SN-611.6` | `Unresolved` | the identifier was not resolved, naming the failing step |
| `SN-611.7` | `NotSchema` | the resolved body is not a valid schema document |
| `SN-611.8` | `Unverified` | signature verification failed |

## Resolution

A signature is authoritative: when layer selections precede it, it must decompose into
exactly the base hash plus the selected layers' hashes, in order. A bare reference (no
selector, no signature) resolves only against local state, by design; make a document
portable by appending a signature or publishing the schema and using a `:version` or `:tag`
selector. A non-network resolver answers `Unresolved` at the LIRA step for anything absent
from local stores.
