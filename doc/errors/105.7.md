# `↯/s.105.7` — `PrivateKey.Error`

Raised when a key document cannot be read as a private key of the cipher asked for.

## Cause

A private key is read from a document — PKCS#8, PKCS#1, SEC1 or OpenSSH's own container, bare
or in PEM armor — as a key of a named cipher, such as `PrivateKey[Ecdsa[256]]`. This error
covers a document that is not a key at all, one that holds a key of another algorithm or
size, and one that cannot be used as it stands.

## Variants

```tabular
column  Code
column  Reason
column  Message
row  `↯/s.105.7.1`  `Malformed`  the key document was malformed: <detail>
row  `↯/s.105.7.2`  `Mismatch`  a <expected> key was expected but <found> was found
row  `↯/s.105.7.3`  `Encrypted`  the key is protected by a passphrase
row  `↯/s.105.7.4`  `Unsupported`  the key uses an unsupported <detail>
row  `↯/s.105.7.5`  `PublicKeyAbsent`  the key does not carry its public key
```

## Resolution

A `Mismatch` names what the document holds: read the key as that cipher, or supply the key
that was intended. A passphrase-protected key must be decrypted before it is read, for
example with `ssh-keygen -p` or `openssl pkcs8`. An EC, Ed25519 or ML-DSA key written without
its public half cannot answer `public`; rewrite it with a tool that includes the public key,
as `openssl pkey` does.
