# `SN-564` — `Font.Error`

Raised when Phoenicia cannot read a font file, or when a face is requested from a provision
that cannot set it.

## Cause

Phoenicia parses font files (typically TrueType/OpenType) and reports
this error when the file is missing required tables, uses an unknown
format, or fails the magic-number check. It also reports it when a `Font` is made from a
`Face` — a weight, slant, stretch, variation or feature — that the typeface's `Typesettable`
provision does not cover, so that the document does not go on to a synthesized or substituted
rendering. The message is `the font could not be used because $reason`.

## Variants

### `SN-564.1` — `MissingTable`

A required table identified by `tag` was not found in the font file.

**Example.** `[↯SN-564.1] the font could not be used because the table cmap was not found`

**Resolution.** Use a font that contains the required tables; many
font subsetting tools can strip mandatory tables.

### `SN-564.2` — `UnknownFormat`

A table was located but its content does not match any version of
the format Phoenicia knows how to read.

**Example.** `[↯SN-564.2] the font could not be used because the table contains data in an unknown format`

**Resolution.** Use a font that conforms to a supported version of
the OpenType/TrueType specification.

### `SN-564.3` — `MagicNumber`

The font's leading bytes did not match the expected magic number,
indicating the file is not a font Phoenicia recognises.

**Example.** `[↯SN-564.3] the font could not be used because the font did not contain expected check data`

**Resolution.** Confirm the file is a TrueType or OpenType font and
not corrupted; check that the file was opened in binary mode.

### `SN-564.4` — `MissingEncoding`

The font declares no character-to-glyph mapping this reader can use.

**Example.** `[↯SN-564.4] the font contains no usable character encoding`

**Resolution.** Use a font with a Unicode `cmap` subtable. A font carrying only a legacy Macintosh or symbol encoding cannot map characters to glyphs.

### `SN-564.5` — `UncoveredWeight`

The provision offers no face at the requested weight.

**Example.** `[↯SN-564.5] the font could not be used because Inter is not provided at weight 700`

**Resolution.** Embed a file at that weight (or a variable font whose `wght` axis spans it),
declare the weight in a linked provision's coverage, or ask for a weight the provision has.

### `SN-564.6` — `UncoveredSlant`

The provision has no italic (or no upright) face.

**Example.** `[↯SN-564.6] the font could not be used because Inter is not provided in an italic face`

**Resolution.** Add the italic file to the provision, or set the face upright.

### `SN-564.7` — `UncoveredStretch`

The provision offers no face at the requested stretch.

**Example.** `[↯SN-564.7] the font could not be used because Inter is not provided at a stretch of 75.0%`

**Resolution.** Add a condensed or expanded file, or use the normal width.

### `SN-564.8` — `UnknownAxis`

The face varies an axis the font does not have.

**Example.** `[↯SN-564.8] the font could not be used because Inter has no variation axis opsz`

**Resolution.** Check the font's `fvar` table for the axes it defines; `Sfnt.fvar` lists them.

### `SN-564.9` — `AxisOutOfRange`

The face sets an axis to a value outside the range the font admits.

**Example.** `[↯SN-564.9] the font could not be used because Inter does not admit 950.0 on its wght axis`

**Resolution.** Keep the value within the axis's minimum and maximum.

### `SN-564.10` — `MissingFeature`

The face enables a layout feature the font's `GSUB` and `GPOS` tables do not implement.

**Example.** `[↯SN-564.10] the font could not be used because Inter does not implement the layout feature onum`

**Resolution.** Use a font that implements the feature, or drop the setting; `Sfnt.features`
lists what a file implements.
