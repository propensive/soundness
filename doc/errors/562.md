# `SN-562` — `XPathError` (retired)

**This code is no longer raised.** A malformed XPath *expression* is now a
`Parse.Error` (`SN-594`) over the `XPath` format, like every other parse
failure in the codebase: `XPath` implements `zephyrine.Format`, as `Xml`
already did, and its former `Reason` cases are now `XPath.Issue`s. The
`Position` still carries the character offset, so the `xp"…"` interpolator
still places its caret exactly.

The name `XPath.Error` now belongs to the distinct failure of *evaluating*
an expression that parsed — see `SN-563`.

Two of the former reasons are gone rather than translated: `ExpectedSlash`
and `BadStep` were raised only by the pre-AST positional parser and were
retained solely to keep the numbering stable. `Issue`s are not numbered, so
nothing needed to hold their place.
