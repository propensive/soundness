# `↯/s.137.1` — `Link.Error`

Raised when linking a compilation into an artifact fails.

## Cause

Linking turns a compilation's output into an executable JAR, a JavaScript bundle, a native
binary or an Android package. This error covers the linker terminating abnormally, and the
entry-point requirements each artifact imposes.

## Variants

### `↯/s.137.1.1` — `Failed`

**Example.** `[↯/s.137.1.1] the linker terminated abnormally`

### `↯/s.137.1.3` — `NoEntryPoint`

**Example.** `[↯/s.137.1.3] the artifact requires exactly one entry point`

### `↯/s.137.1.4` — `ManyEntryPoints`

**Example.** `[↯/s.137.1.4] an executable JAR permits at most one entry point`

### `↯/s.137.1.11` — `CompilationFailed`

**Example.** `[↯/s.137.1.11] compilation failed with 2 errors`

The reason carries every diagnostic the compiler reported, as `notices`.


## Resolution

An executable JAR permits at most one entry point and a native executable requires exactly
one; the reason says which rule was broken. A linker that terminated abnormally carries its
stack trace.

> This error previously used the code `↯/s.137.3`, which collided with `CompilerError`.
