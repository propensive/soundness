# `SN-608` — `Varint.Error`

Raised when a variable-length integer in BinTEL is malformed.

## Cause

BinTEL encodes integers as varints, seven bits per byte with a continuation flag. This error
covers a varint that runs past the end of the input, one wider than the 64 bits the format
permits, and one that is not minimal — an overlong encoding such as `80 00` for zero, which
§4 of the BinTEL specification rejects so that every integer has exactly one encoding.

## Variants

### `SN-608.1` — `Truncated`

**Example.** `[↯SN-608.1] the varint is truncated — a continuation byte was expected`

### `SN-608.2` — `Overflow`

**Example.** `[↯SN-608.2] the varint encodes a value that does not fit in 64 bits`

### `SN-608.3` — `Overlong`

**Example.** `[↯SN-608.3] the varint is not minimal — its last byte carries no payload bits`

## Resolution

The stream is truncated or corrupt. A varint longer than the target type permits usually
means reader and writer disagree about the field's type. An overlong varint comes from an
encoder that pads, which no conforming BinTEL encoder does.
