# Changes since 0.77.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.77.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## breviloquence

- The `Map[key, element]` decoded by the given `breviloquence.Cbor.mapDecodable` (`Map[key, element]
  is Decodable in Cbor`) is filled with `proscenium.Map.build`. A result of five or more entries is
  backed by a flat hash table, so its iteration order differs from before; neither order is
  specified, and a result of four or fewer entries still iterates in document order. Contents,
  equality and `hashCode` are unchanged. (#2532)

## denominative

- The givens `denominative.Applicable.map` and `denominative.Applicable.hashMap` are typed
  `Map[key, value] is Applicable.Probing` and `scala.collection.mutable.HashMap[key, value] is
  Applicable.Probing`; they were `… is Applicable`. `Applicable` gains `def probe(value: Self,
  index: Operand): Optional[Result]`, concrete, defaulting to `contains` then `access`;
  `Applicable.Probing` is a new subtrait of `Applicable` with no members of its own, whose
  instances override `probe`. The checked `at` and `apply` extensions (`rudiments`, from
  `concordance`) call `probe` once where the receiver's `Applicable` instance is statically a
  `Probing`, instead of `contains` then `access`; for any other receiver they are unchanged.
  Results are the same. A map's key is now hashed
  and compared once per checked read rather than twice, which is observable only through a
  key type whose `hashCode` or `equals` has side effects. (#2531)

## murmuration

- `xs.to[Map]` (the given `murmuration.Convertible.map`) builds its result with
  `proscenium.Map.build` instead of the standard library's map builder. A result of five or more
  entries is backed by a flat hash table rather than `scala.collection.immutable.HashMap`, so
  its iteration order — as seen by `each`, `fold`, `remap`, `keys`, `values`, `inspect` and
  `.stdlib.iterator` — differs from before; neither order is specified. A result of four or
  fewer entries still iterates in insertion order. Equality, `hashCode`, `at`, `defines`,
  `define`, `omit` and which of two pairs with equal keys is kept (the later) are unchanged.
  The runtime class of such a result's `.stdlib` is no longer `HashMap`; it is still a
  `scala.collection.immutable.Map`. Code that depends on the order must sort, or use `Ledger`.
  (#2531)

- A pairwise reshape of a `Map` into a `Map` (the given `murmuration.Reshapable.map`, behind
  `remap`, `filter`, `bind` and the other reshaping operations when their result is a `Map`) and
  `group` fill their result with `proscenium.Map.build`. As for `xs.to[Map]` above, a result of five
  or more entries iterates in a different, still unspecified, order. (#2532)

## proscenium

- `proscenium.Map.apply(pairs*)` (a map literal), `proscenium.Map.from(pairs)` for a source that is
  not already a map, the stdlib-factory form `xs.to(Map)` for the same sources, and the
  value-mapping `map` on a `Map` fill their result in place, as `proscenium.Map.build` does. A
  result of five or more entries is backed by a flat hash table rather than
  `scala.collection.immutable.HashMap`, so its iteration order — as seen by `each`, `fold`, `remap`,
  `keys`, `values`, `inspect` and `.stdlib.iterator` — differs from before; neither order is
  specified. A result of four or fewer entries iterates in the order its entries were given, as
  before. `Map.from` of a value that is already a map still returns it unchanged. Equality,
  `hashCode`, `at`, `defines`, `define` and `omit` are unchanged; the runtime class of such a
  result's `.stdlib` is no longer `HashMap`. Code that depends on a map's order must sort, or use
  `Ledger`. (#2532)

## tasseomancy

- The chart kind `tasseomancy.Doughnut` is renamed `tasseomancy.Annulus`, and with it the members
  of its companion: `Doughnut()` is `Annulus()`, `Doughnut.Fit[node]` is `Annulus.Fit[node]`,
  `Doughnut.Style` is `Annulus.Style` and the given `Doughnut.dag` is `Annulus.dag`. The `soundness`
  package exports `Annulus` in place of `Doughnut`. Replace the identifier `Doughnut` with
  `Annulus` wherever it refers to this type; nothing else about the chart, its fit, its style or
  the SVG it draws has changed. (#TBD)
