# Changes since 0.73.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.73.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## stenography

- `stenography.Bindings`'s constructor `Bindings(pureFuns: Boolean = true, infixAliases:
  scala.collection.immutable.Map[String, Text] = Map())` is now `Bindings()`, and its members
  `pureFuns` and `infixAliases` are removed. A `Syntax` tree no longer depends on either: pass
  purity to `Syntax#text` as the new last field of `stenography.Imports`, `pureFuns: Boolean =
  true`, and infix aliases as `Imports#aliases`, which was already consulted. Code that built
  `Bindings(false)` to render `=>` arrows must now render with `Imports(…, pureFuns = false)`.
  (#2318)
- `stenography.Syntax.apply` no longer writes an infix type alias into the tree: a refinement
  `Foo { type Form = Bar }` is always built as `Syntax.Structural`, and `Syntax#text` writes it
  `Foo in Bar` when `Imports#aliases` maps `Form` to `in`. A type member which is an alias
  (`type Form = Bar`) is now stored in the `Structural`'s `types` ledger as the bare `Syntax` of
  `Bar`, not as `Syntax.Declaration(false, Nil, …)`; a bounded member is still a `Declaration`.
  Code that pattern-matches `Structural` members for `Declaration` must accept a bare `Syntax`
  for alias members. (#2318)
- `stenography.Syntax.apply` no longer chooses the arrow of a function type or by-name type by
  the call site: a `Syntax.Function`'s `impure` is now `false` for a bare `FunctionN` and for a
  method type even where pure functions are off, and an unannotated by-name type is always
  `Syntax.Prefix("->", …)`. `Syntax#text` writes both with `=>` when `Imports#pureFuns` is
  `false`, so rendered text is unchanged. Code that inspects `Function#impure` or a
  `Prefix`'s operator directly must take `Imports#pureFuns` into account. (#2318)
- `stenography.internal.name` now shares one `Bindings` across all calls in a compilation run,
  so the binder of a recursive type (`RecursiveThis`) may be numbered (`x2`, …) where a type
  rendered earlier in the same run used the same candidate name; previously numbering started
  afresh at every call. (#2318)
- `stenography.Designator` now defines `equals` and `hashCode` itself (structural, with the hash
  cached), and `Designator.apply(text)`, `Designator#child`, `#companionObject` and
  `#companionType` return interned instances, so equal designators made through them are `eq`.
  Equality is unchanged. (#2318)

## frontier

- `frontier.Diagnostic.render(diagnostic: Diagnostic, headline: Text = …): Text` is now
  `render(diagnostic: Diagnostic, headline: Text = …, limit: Int = 100): Text`. It writes at most
  `limit` lines of the tree, followed by a line `… n more` when `n` lines were omitted, and
  writes a non-leaf subtree identical to one already written as its first line alone, with the
  label `as above` (or `<label>, as above` where it has a label). (#2318)
- The `explainMissingContext` catch-all now charges each expansion of classpath proposals to the
  same budget of 256 as its implicit searches, so in a large scope an explanation can list
  fewer proposals than before. (#2318)

## stratiform

- `Tels.tels[value](name)` now names the record and select definitions of a derived schema by
  *type*, not by simple name. A type whose simple name no other type in the schema shares keeps
  it, so the schema of a type without clashes is unchanged (same definitions, same hash, same
  BinTEL layout). Where two or more distinct types share a simple name — `Phrase.Code` and
  `Element.Code` — every member of the group is named by its enclosing types as a TypeName,
  `PhraseCode` and `ElementCode`, deepening (`PkgPhraseCode`) only until the names differ.
  Previously the first such definition found was kept and the others silently dropped, so that
  writing a value under the schema failed with `SN-605.217` (a reference resolving to a
  definition of the wrong kind) or was checked against the wrong definition. A hand-written
  schema, or TEL text, that names a derived definition of a clashing type must use the qualified
  name. (#2319)
- `Tels.tels` now declares `raises Tel.Error`: a clash the qualification cannot tell apart (two
  types that qualify to one name, or a type whose own name is one the clashing group qualifies
  to) is reported as E210 (`Tel.Error.Reason.DuplicateDefinition`) when the schema is derived,
  and the assembled schema is checked as a hand-written one is (`Tels.Validation`'s base checks:
  E202, E207, E210, E216, E222). Callers without a `Tactic[Tel.Error]` in scope must provide one
  (an `import strategies.throwUnsafely`, a `safely`/`unsafely` block, or `raises Tel.Error` on
  the enclosing method). `Tel.Acceptance.lineage` and `Tel.Acceptance.lineages` take the same
  `Tactic[Tel.Error]`; `Tel.Acceptance.apply`, `otherwise`, `fulfil`, `Bintel.read`,
  `value.bintel` and `Duplex#framed` already did. (#2319)
- `TelSchematic`'s derivation protocol is keyed on `TelSchematic.Identity` and threads a
  `TelSchematic.Naming`: `fieldType`, `selectDefinitions` and `rootLayers` take a `naming`
  parameter; `definitions` and `layers` take `(seen: Set[TelSchematic.Identity], naming)` in
  place of `(seen: Set[Text])`; `schema(naming)` is added beside the unparameterised `schema()`
  (which names every type by its simple name); and `identities(seen)` is new. The helpers
  `TelSchematic.fieldTypeOf`, `definitionsOf` and `layersOf` take the extra parameters, and
  `TelSchematic.schemaOf` and `identitiesOf` are added. A hand-written `TelSchematic` that
  overrode any of these must adopt the new signatures; one implementing only `schema()` (the
  scalar form, `() => Tels.Scalar(…)`) is unaffected. (#2319)
