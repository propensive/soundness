# Changes since 0.73.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.73.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## stenography

- `stenography.Bindings`'s constructor `Bindings(pureFuns: Boolean = true, infixAliases:
  scala.collection.immutable.Map[String, Text] = Map())` is now `Bindings()`, and its members
  `pureFuns` and `infixAliases` are removed. A `Syntax` tree no longer depends on either: pass
  purity to `Syntax#text` as the new last field of `stenography.Imports`, `pureFuns: Boolean =
  true`, and infix aliases as `Imports#aliases`, which was already consulted. Code that built
  `Bindings(false)` to render `=>` arrows must now render with `Imports(…, pureFuns = false)`.
  (#2320)
- `stenography.Syntax.apply` no longer writes an infix type alias into the tree: a refinement
  `Foo { type Form = Bar }` is always built as `Syntax.Structural`, and `Syntax#text` writes it
  `Foo in Bar` when `Imports#aliases` maps `Form` to `in`. A type member which is an alias
  (`type Form = Bar`) is now stored in the `Structural`'s `types` ledger as the bare `Syntax` of
  `Bar`, not as `Syntax.Declaration(false, Nil, …)`; a bounded member is still a `Declaration`.
  Code that pattern-matches `Structural` members for `Declaration` must accept a bare `Syntax`
  for alias members. (#2320)
- `stenography.Syntax.apply` no longer chooses the arrow of a function type or by-name type by
  the call site: a `Syntax.Function`'s `impure` is now `false` for a bare `FunctionN` and for a
  method type even where pure functions are off, and an unannotated by-name type is always
  `Syntax.Prefix("->", …)`. `Syntax#text` writes both with `=>` when `Imports#pureFuns` is
  `false`, so rendered text is unchanged. Code that inspects `Function#impure` or a
  `Prefix`'s operator directly must take `Imports#pureFuns` into account. (#2320)
- `stenography.internal.name` now shares one `Bindings` across all calls in a compilation run,
  so the binder of a recursive type (`RecursiveThis`) may be numbered (`x2`, …) where a type
  rendered earlier in the same run used the same candidate name; previously numbering started
  afresh at every call. (#2320)
- `stenography.Designator` now defines `equals` and `hashCode` itself (structural, with the hash
  cached), and `Designator.apply(text)`, `Designator#child`, `#companionObject` and
  `#companionType` return interned instances, so equal designators made through them are `eq`.
  Equality is unchanged. (#2320)

## frontier

- `frontier.Diagnostic.render(diagnostic: Diagnostic, headline: Text = …): Text` is now
  `render(diagnostic: Diagnostic, headline: Text = …, limit: Int = 100): Text`. It writes at most
  `limit` lines of the tree, followed by a line `… n more` when `n` lines were omitted, and
  writes a non-leaf subtree identical to one already written as its first line alone, with the
  label `as above` (or `<label>, as above` where it has a label). (#2320)
- The `explainMissingContext` catch-all now charges each expansion of classpath proposals to the
  same budget of 256 as its implicit searches, so in a large scope an explanation can list
  fewer proposals than before. (#2320)

## stratiform

- `Tels.tels[value](name)` now names the record and select definitions of a derived schema by
  *type*, not by simple name. A type whose simple name no other type in the schema shares keeps
  it, so the schema of a type without clashes is unchanged (same definitions, same hash, same
  BinTEL layout). Where two or more distinct types share a simple name — `Phrase.Code` and
  `Element.Code` — every member of the group is named by its enclosing types as a TypeName,
  `PhraseCode` and `ElementCode`, deepening (`PkgPhraseCode`) only until the names differ.
  Previously the first such definition found was kept and the others silently dropped, so that
  writing a value under the schema failed with `SN-605.217` (a reference resolving to a
  definition of the wrong kind) or was checked against the wrong definition. A hand-written
  schema, or TEL text, that names a derived definition of a clashing type must use the qualified
  name. (#2321)
- `Tels.tels` now declares `raises Tel.Error`: a clash the qualification cannot tell apart (two
  types that qualify to one name, or a type whose own name is one the clashing group qualifies
  to) is reported as E210 (`Tel.Error.Reason.DuplicateDefinition`) when the schema is derived,
  and the assembled schema is checked as a hand-written one is (`Tels.Validation`'s base checks:
  E202, E207, E210, E216, E222). Callers without a `Tactic[Tel.Error]` in scope must provide one
  (an `import strategies.throwUnsafely`, a `safely`/`unsafely` block, or `raises Tel.Error` on
  the enclosing method). `Tel.Acceptance.lineage` and `Tel.Acceptance.lineages` take the same
  `Tactic[Tel.Error]`; `Tel.Acceptance.apply`, `otherwise`, `fulfil`, `Bintel.read`,
  `value.bintel` and `Duplex#framed` already did. (#2321)
- `TelSchematic`'s derivation protocol is keyed on `TelSchematic.Identity` and threads a
  `TelSchematic.Naming`: `fieldType`, `selectDefinitions` and `rootLayers` take a `naming`
  parameter; `definitions` and `layers` take `(seen: Set[TelSchematic.Identity], naming)` in
  place of `(seen: Set[Text])`; `schema(naming)` is added beside the unparameterised `schema()`
  (which names every type by its simple name); and `identities(seen)` is new. The helpers
  `TelSchematic.fieldTypeOf`, `definitionsOf` and `layersOf` take the extra parameters, and
  `TelSchematic.schemaOf` and `identitiesOf` are added. A hand-written `TelSchematic` that
  overrode any of these must adopt the new signatures; one implementing only `schema()` (the
  scalar form, `() => Tels.Scalar(…)`) is unaffected. (#2321)
- `stratiform.Tel.Provider` record fields now fail with the new
  `stratiform.Tel.Provider.Error(reason: Tel.Provider.Error.Reason)` (`SN-614`), raised through the
  `Tactic` of the code reading the field. `Tel.Provider.Error.Reason` has `Absent(name: Text)` (1)
  and `NotSigil(value: Text)` (2). A required field which is absent now raises
  `Tel.Provider.Error(Absent(name))` where it raised `Tel.Error(Tel.Error.Reason.Absent)`;
  handlers and `capture`s of `Tel.Error` for a missing field must catch `Tel.Provider.Error`.
  `Tel.Provider#Failure` is `Tel.Provider.Error`, and `Tel.Provider#access`, `#required` and
  `#repeated` take `(using Tactic[Tel.Provider.Error])`. (#2325)
- The `"sigil"` reader of `Tel.Provider` (`Tel.Provider.sigil`) is now an
  `Intensional.Reading["sigil", Tel.Provider, Tel, Char, Tel.Provider.Error]`, and an atom of
  other than one character raises `Tel.Provider.Error(NotSigil(atom))`, where it read as `'#'`.
  (#2325)
- A field (or `List`, `Set`, `Optional` or `Map` element, or select variant) whose type is a sum
  now derives, in `Tels.tels` and `TelSchematic`, as a `Tels.Reference` to a new record definition
  named `<Sum>Value` (`FigurineValue` for `Figurine`, qualified as the sum's own name is), which
  holds one `Tels.SelectRef(Implicit, Implicit, <Sum>)`, where it derived as a
  `Tels.Reference(<Sum>)` to the sum's select, which is invalid (E217) and could not be written as
  BinTEL. The select keeps the sum's name. The derived schema of every type with a sum-typed
  member gains these records, so its hash and BinTEL signature change; a schema whose only sum is
  its root (a `SelectRef` at the document root) is unchanged. A hand-written schema or a
  `Tels.Reference` naming the sum for such a member must name `<Sum>Value`. A user type named
  `<Sum>Value` beside a sum `<Sum>` now clashes, as E210. (#2327)

## polyvinyl

- `polyvinyl.Specification` has a new abstract type member, `type Failure <: Hazard`: the error
  every field of its records may raise. Every implementation must declare it. (#2325)
- These `polyvinyl.Specification` hooks gain a `(using Tactic[Failure])` clause, which every
  override must add: `access(name: Text, value: Origin): Origin`, `repeated(name: Text, value:
  Origin): List[Origin]`, `required(name: Text, value: Origin): Origin`, `entries(name: Text,
  value: Origin): List[(Text, Origin)]`, `elements(value: Origin): List[Origin]` and
  `pairs(value: Origin): List[(Text, Origin)]`. `absent`, `kind` and `build` are unchanged.
  (#2325)
- New hook `polyvinyl.Specification#unoffered(kind: Text, offered: List[Text])(using
  Tactic[Failure]): Nothing`, applied to a value of a union whose kind no alternative offers. Its
  default panics, as the dispatch did before. (#2325)
- Every field of a record a `Specification` builds now has the type `polyvinyl.Record.Field[T,
  Failure]` (a new alias, `Tactic[failure]^ ?-> result`), where it had the type `T` (or `T raises
  E` for a field read by an `Intensional.Fallible`). Selecting the field applies it to the
  `Tactic[Failure]` in scope, so code reading a field needs one (`strategies.throwUnsafely`
  restores the old throwing behaviour). A field's value of type `Optional[T]`, `List[T]` or
  `Map[Text, T]` keeps its shape inside the `Field`. (#2325)
- `polyvinyl.Record#selectDynamic(name)` now returns the field's reading, the context function
  `Tactic[Failure] ?-> T`, where it returned the value; code selecting a field by name must cast
  the result to `Record.Field[T, Failure]` (or `T raises Failure`) and apply it to a `Tactic`.
  (#2325)
- `Specification#tuple` now summons a `Tactic[Failure]` where the tuple is built, for every
  field, and does not compile without one; previously only tuples with fallible fields needed
  one, for their own error types. (#2325)
- An `Intensional.Fallible` instance whose `Error` does not conform to the specification's
  `Failure` is now a compile error at the `record` or `tuple` call ("the instance for <label>
  raises <error>, not the specification's <failure>"). (#2325)
- The macro entry points take the failure type as a new last type parameter: `Specification.record`
  and `Specification.tuple` are `[self, origin, form, failure <: Hazard]`, and
  `Specification.recordExpansion` and `Specification.tupleExpansion` are `[origin, form, failure
  <: Hazard]`, with `target: Expr[Specification.Raising[form, origin, failure]]` (a new alias for
  `(Specification in form from origin) { type Failure = failure }`) in place of `Expr[Specification
  in form from origin]`. (#2325)

## jacinta

- `jacinta.Json.Provider` record fields now raise `Json.Provider.Error` through the `Tactic` of
  the code reading the field for every failure, where schema violations were thrown whatever
  tactic was in scope, so `attempt`, `recover`, `validate` and `track` now see them. A required
  property which is absent raises `Json.Provider.Error(MissingValue(name))`, where it raised
  `Json.Error(Json.Error.Reason.Absent)`; a value of the wrong JSON type raises
  `Json.Provider.Error(JsonType(expected, found))`, where it raised
  `Json.Error(Json.Error.Reason.NotType(found, expected))`. Handlers and `capture`s of
  `Json.Error` around record fields must catch `Json.Provider.Error` instead. (#2325)
- `Json.Provider.Error.Reason.MissingValue` is now `MissingValue(name: Optional[Text])`, the
  missing field's name where it is known. New reasons: `UnexpectedKind(found: Text, offered:
  List[Text])` (`SN-624.8`), for a union value of a kind none of its alternatives offers, which
  previously panicked; and `Unparsable(value: Text, format: Text)` (`SN-624.9`), for a
  `json-pointer` or `regex` string which does not parse, which previously threw
  `JsonPointer.Error` or `Regex.Error`. (#2325)
- `Json.Provider.Primitives#Failure` is `Json.Provider.Error`. The `Json.Provider` readers
  `boolean`, `string`, `integer`, `long`, `number` and every format reader (`dateTime`, `date`,
  `time`, `duration`, `uriReference`, `email`, `idnEmail`, `hostname`, `ipv4`, `ipv6`, `uri`,
  `iri`, `iriReference`, `uuid`, `uriTemplate`, `jsonPointer`, `regex`) are now givens of the new
  `Json.Provider.Reader[label, result]` (an alias of `Intensional.Reading[label, Json.Provider,
  Json, result, Json.Provider.Error]`), where they were plain `Intensional` instances. (#2325)

## xylophone

- `xylophone.Xml.Provider` record fields now raise `Xml.Provider.Error` through the `Tactic` of
  the code reading the field for every failure: a missing required element or attribute
  (`Absent`, which was thrown), and a value its type cannot read, which raised `Xml.Error` and
  now raises the new `Xml.Provider.Error.Reason.Malformed(value: Optional[Text], expected:
  Text)` (`SN-993.7`). Handlers of `Xml.Error` around record fields must catch
  `Xml.Provider.Error` instead. (#2325)
- `Xml.Provider#Failure` is `Xml.Provider.Error`. The readers of the builtin types (`string`,
  `boolean`, `int`, `long`, `short`, `byte`, `double`, `float`, `decimal`, `dateTime`, `date`,
  `time`, `duration`, `anyUri`, and the `Text` fallbacks `dateTimeText`, `dateText`, `timeText`,
  `durationText`, `anyUriText`) are now givens of the new `Xml.Provider.Reader[label, result]`
  (an alias of `Intensional.Reading[label, Xml.Provider, Xml, result, Xml.Provider.Error]`).
  (#2325)

## apoplexy

- `apoplexy.Api.Records.list(json, transform)` now takes `(using Tactic[Json.Provider.Error])`,
  and a response read with `record()` or `tuple()` whose schema is an array needs a
  `Tactic[Json.Provider.Error]` where the macro is expanded, failing to compile without one. The
  fields of response records, and of error payload records, are `Record.Field`s like any other
  `Json.Provider` record's. (#2325)

## proscenium

- `List.prepend` and `List.append` now return `List[element] & Populated` rather than
  `List[element]`: adding an element makes the list non-empty, so the result carries the
  proof and `head`, `last` and `reduce` are total on it, as they already were on `List(a, b)`
  literals. The infix `head :: tail` is unchanged (a right-associative chain cannot infer its
  element type from a branded right operand), so code that needs the proof from a cons should
  call `List.prepend(tail, head)`. (#TBD)

## gossamer

- `Text#cut` (and `cut` on every `Cuttable` textual) returns `List[textual] & Populated`
  rather than `List[textual]`: a cut always yields at least one piece (the text after the
  last delimiter, or the whole text), so `text.cut(t",").head` and `.last` are total; the
  partial `text.cut(t",").stdlib.head` can become `.head`. A `limit` of zero or less is now
  read as unlimited (`Int.MaxValue`); previously a zero limit on a `Text` cut by `Regex` had
  `String.split`'s semantics, dropping trailing empty pieces and possibly yielding nothing.
  The generic `textual is Cuttable by Regex` instance (any `Textual` with `Countable`, other
  than `Text` itself) now returns the pieces *between* matches, including the text after the
  last match, like every other instance; it previously returned the matched regions and an
  empty list when there was no match. (#TBD)

## digression

- `Fqcn#parts` is typed `Array[Text]^{} & Populated` rather than `Array[Text]^{}`, and the
  `Fqcn` constructor takes that type: a fully-qualified class name has at least one part, which
  is what makes `className` total. `Fqcn.apply(name)` is unchanged (it proves the type with
  `occupied`, aborting with `Fqcn.Error.Reason.EmptyName` as before); code calling
  `new Fqcn(array)` directly must pass a `Populated` array — `array.occupied.or(…)`. (#TBD)

## galilei

- `Searchpaths.Stems#stems` is declared `List[Path on Target] & Populated` rather than
  `List[Path on Target]`: the head stem is where writes go, so the contract was already
  non-emptiness. An implementation that builds the list with `::` or a `List(…)` literal
  typechecks unchanged; one that returns an arbitrary `List` must prove it with
  `list.occupied.or(…)`. (#TBD)

## denominative

- `ult` is now `transparent inline` and adapts to a `Populated` receiver, as rudiments'
  `last` does: on `xs: List[T] & Populated` it returns `Ordinal in xs.type` rather than
  `Optional[Ordinal in xs.type]`, so `xs(xs.ult)` is total with no `let`. On other receivers it
  is unchanged. (#TBD)

## rudiments

- `head`, `lead` and `tail` now *adapt* to what the receiver's type proves, as `last` already
  did: on a receiver typed `& Populated` (a `List(a, b)` literal, a `cut`, a `List.prepend`, an
  `occupied` result) they are total and return the element, the leading segment or the trailing
  segment; on any other receiver they return `Optional[…]`, `Unset` when the value is empty.
  Previously `head` and `lead` existed only for `Populated` receivers and `tail` was total
  everywhere (an empty value's tail was empty). Code that called `xs.tail` on an unproven
  receiver and used the result as a collection must now discharge the `Optional`
  (`xs.tail.or(Nil)` keeps the old behaviour) or prove the receiver non-empty. (#TBD)
- `prim`, `sec` and `ter` (on `List`, `Chain` and any `Applicable` by `Ordinal`, in `rudiments`
  and the umbrella) are removed. `xs.prim` is `xs.head`, which now has exactly its type on an
  unproven receiver (`Optional[element]`) and is total on a `Populated` one; `xs.sec` and
  `xs.ter` are `xs.at(Sec)` and `xs.at(Ter)` (on a `List` these open the `linearAccess` gate,
  which the bounded special cases did not). (#TBD)
