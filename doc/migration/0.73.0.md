# Changes since 0.72.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.72.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## zephyrine

- New: `zephyrine.Cursor.Snapshot[medium, operand]`, an inline trait (Scala 3.10,
  `-language:experimental.inlineTraits` is needed only by zephyrine, not by a consumer) that a
  fast parser over a `Cursor[medium, {}]` extends to get the parser-local snapshot of the
  cursor's buffer that jacinta, xylophone, stratiform, ypsiloid, honeycomb, locomotion and
  breviloquence previously each wrote out by hand: the fields `cells: scala.Array[operand]`
  (a `byte[]` for `Snapshot[Data, Byte]`, a `char[]` for `Snapshot[Text, Char]`), `pos`,
  `bufEnd`, `base`, `lineationPos` and `cursor0: AnyRef` (the cursor, re-pointed at each
  reset), the accessor `cursor`, and `syncTo()`, `syncFrom()`, `more`, `moreSlow()`, `peek`,
  `advance()`, `position`, `reconcileLineation()`, `reconcileUtf8()` and `reconcileUtf16()`.
  A parser extending it must be a `caps.Stateful` class and implement the two abstract hooks
  `protected update def reconcile(): Unit` (called before every refill) and `protected update
  def resynced(): Unit` (called after every `syncFrom()`), as `()` where it has nothing to do.
  It must not override any other member: an inline trait's own calls to a member the
  receiver overrides bind to the trait's copy, not to the override. No existing API changed.
- `zephyrine.Cursor` extension methods `peek: Datum` and `expect[error <: Hazard](target: Char)
  (failure)(using Tactic[error])`, previously defined twice, as `@targetName("peekByte")`/
  `("peekChar")` and `("expectByte")`/`("expectChar")` extensions on `Cursor[Data, cap]` and
  `Cursor[Text, cap]`, are now one definition each, on `Cursor[data, cap]` with an additional
  `(using data is Addressable)` clause on the extension (resolved from the medium's companion,
  so no import changes), selecting the byte or char read by the medium's `Operand`. Call
  sites are unchanged; a cursor over any other medium gets a compile-time error from `peek`,
  where it previously had no `peek` at all. (#2279)
- `zephyrine.Cursor#seek(target: addressable.Operand): Boolean` is no longer `inline`
  (a plain `update def`); same semantics, and it now compares bytes and chars without
  boxing. (#2279)

## baroque

- `baroque.Complex[component]` is no longer a case class but a `sealed abstract class` with two
  final subclasses in its companion, chosen by the component's runtime class:
  `Complex.Doubles[component](real: Double, imaginary: Double)` for any component that is a
  `Double` underneath (`Double` itself, a quantity, an `F64` — anything with `Underlying[_,
  Double]` evidence), and `Complex.Boxed[component](real: component, imaginary: component)`
  otherwise. `Complex(real, imaginary)`, `complex.real`, `complex.imaginary`, `argument`,
  `modulus`, `sqrt`, `unary_~`, equality, hashing, `toString` (`Complex(1.0, 2.0)`) and every
  typeclass instance are unchanged in use, and `case Complex(real, imaginary)` still matches.
  Gone are the case-class extras: `copy`, `Product` membership (`productElement`,
  `productArity`) and `Complex.curried`/`tupled`. The constructor, accessors and arithmetic
  instances are `inline`: `c + d`, `c*d`, `c/d`, `-c` and `c*2.0` on `Complex[Double]`s compile to
  primitive arithmetic with one allocation of two unboxed fields per result, where each
  previously allocated an object and two boxed doubles and unboxed them on every read. The
  arithmetic instances' result types are now type parameters inferred through their `using`
  clauses rather than the parameters' `Result` members; summoning them by name as values still
  works. (#2286)

## hypotenuse

- The arithmetic instances of `Q64` and `Q32` (`addable`, `subtractable`, `multiplicable`,
  `divisible`, `negatable`, and the `Double`/`Int`/`Long`-operand `multiplicable…`/`divisible…`
  variants) are `inline given`s with `inline def` operations, so a use that reaches one at its
  own type — symbolism's operators, mosquito's and baroque's inline instances — performs the
  `Long` arithmetic with no instance call and no boxing: `Vector[Q64, n] + Vector[Q64, n]` is a
  loop of `laload`/`lastore` around the rational sum. Types and names are unchanged;
  `negatable` is a structural instance rather than a lambda. (#2287)

## mosquito

- `mosquito.Vector[value, size]` now stores its elements in an `Array[value]^{}` (a `double[]`
  for a `Vector[Double, 3]`, likewise for a quantity, whose opaque type erases to `Double`)
  rather than an `Array[Any]^{}` of boxed elements, so `Vector#data` has that type and
  `Vector#iarray` no longer takes a `ClassTag`. `Vector.apply(tuple)` therefore takes a `using
  ClassTag[Tuple.Union[tuple.type]]`: a tuple of mixed element types, which has none, is
  rejected where it was previously accepted. `Vector.take[element: ClassTag]`,
  `Vector#map[left2: ClassTag]` and `List#slide[element: ClassTag]` gained the bound. The
  3-vector `cross` is typed `Vector[subtraction.Result, 3]` and the 7-vector `cross`
  `Vector[multiplication.Result, 7]` — the types of the values they always held (the same
  types as before for every primitive) — and each takes a `ClassTag` of that result. (#2285)
- The arithmetic instances of `Vector` and `Matrix` (`addable`, `subtractable`, `negatable`,
  `scalarMultiplicable`, `scalarDivisible`, `matrixMultiplicable`, `vectorMultiplicable`) are
  `inline given`s with `inline def` operations, which resolve the element arithmetic at the call
  site (an `AddOp`/`MulOp`/… first, else the `Addable`/… instance at its own type), so `v + w`,
  `m*n`, `m*2.0`, `v.dot(w)` and `v.norm` on `Double` elements compile to loops of
  `daload`/`dadd`/`dmul`/`dastore` with no boxing. `Vector`'s `negatable` and `vectorMultiplicable`
  take a `ClassTag[result]`; `dot` and `norm` are `inline`. Code that summoned one of these
  instances by name as a value still can. (#2285)

## rudiments

- New: `rudiments.Scroll[element]` (in the `concordance` module, like `Scribe`), a growable array
  appended to and indexed by position — the unboxed replacement for `scala.collection.mutable.
  ArrayBuffer[Int|Long|Byte|…]`, whose backing store holds boxed elements. `Scroll[Int]()`
  (optionally with a capacity), then `append(value)`, `append(other: Scroll[element])`,
  `append(array, from, count)`, `apply(index: Int)`, `update(index: Int, value)`, `length`,
  `isEmpty`, `last`, `retract(count)` (forgets the last `count` elements), `clear()` and
  `freeze: Array[element]^{}` (an exact-size frozen copy). Indices are plain `Int`s checked
  against `length`. Not exported by the `soundness` umbrella (as `Scribe` is not); it is reached
  through `import rudiments.*`. jacinta, xylophone and ypsiloid's position-index buffers,
  jacinta's BCD number buffers, turbulence's `StreamOutputStream`, escapade's style stacks,
  exegesis's line index and facsimile's `Gathering` now use it. (#2283)

## symbolism

- The primitive arithmetic instances in `symbolism.Addable`, `Subtractable`, `Multiplicable`,
  `Divisible` and `Negatable` (`double`, `float`, `long`, `int`, `short`, `byte`, and the mixed
  `int2`/`int3`/`double2`/`float2`/`float3`/`long2`/`short2`/`byte2`) keep their names but are
  now `inline given`s typed by singleton objects — `Addable.DoubleAddition.type`,
  `Subtractable.IntSubtraction.type`, `Divisible.FloatDoubleDivision.type`, `Negatable.LongNegation.type`
  and so on — whose `add`/`subtract`/`multiply`/`divide`/`negate` are `inline def`s. Code that
  summons `Double is Addable by Double to Double` still gets them; code that named the given's
  previous type (`val a: Double is Addable by Double to Double = Addable.double`) still compiles
  by widening. Inline code that reaches one through symbolism's `+`, `-`, `*`, `/` or `unary_-`
  now compiles to the primitive instruction instead of a boxed `Function2` call. (#2282)

## enigmatic

- New cipher `enigmatic.Ed25519` (RFC 8032; `Cipher & Signing`, `Size = 256`, no size parameter,
  no `Signature.Digest`), reached through the JDK provider's new structural member
  `def ed25519: Crypto.SignatureScheme`; `Ed25519 is SignatureAlgorithm` (x509) lets a certificate
  be signed with it. Additive. (#2243)
- Existing private keys can now be read. `PrivateKey[cipher]` has `Decodable in Der` (PKCS#8
  `PrivateKeyInfo`) and `Decodable in Pem` (labels `PRIVATE KEY`, `RSA PRIVATE KEY`, `EC PRIVATE
  KEY`, `OPENSSH PRIVATE KEY`) givens for every `cipher` with a `KeyAlgorithm` (Rsa, Ecdsa,
  Ed25519, MlDsa, Dsa), each needing a `Cloak^` and `Tactic[PrivateKey.Error]`: write
  `text.read[PrivateKey[Ed25519] in Pem]`, `pem.as[PrivateKey[Rsa[2048]]]` or
  `der.as[PrivateKey[Rsa[2048]]]`. The document's algorithm, curve and size are checked against
  `cipher`; a `PrivateKey.Error` has reason `Malformed(detail)`, `Mismatch(expected, found)`,
  `Encrypted` (passphrase-protected keys are not yet read), `Unsupported(detail)` or
  `PublicKeyAbsent` (an EC, Ed25519 or ML-DSA PKCS#8 key written without its optional public key).
  Additive. (#2243)
- `PublicKey[cipher]` likewise has `Decodable in Der` (SubjectPublicKeyInfo) and `Decodable in Pem`
  (`PUBLIC KEY`, `RSA PUBLIC KEY`) givens raising `PublicKey.Error` (`Malformed`, `Mismatch`,
  `Unsupported`). New `enigmatic.OpenSsh` reads OpenSSH's single-line public-key form with
  `OpenSsh.publicKey[cipher](line: Text): PublicKey[cipher]` and writes it with
  `OpenSsh.line(key: PublicKey[cipher], comment: Optional[Text] = Unset): Optional[Text]`. Additive.
  (#2243)
- New typeclass `enigmatic.KeyAlgorithm` (`cipher is KeyAlgorithm`: `name`, `sshName`,
  `conforms(algorithm: Asn1, material: KeyAlgorithm.Material)`), with givens in each cipher's
  companion; and `enigmatic.Pkcs8`/`enigmatic.Spki` helpers for the two key-document shapes.
  Additive. (#2243)
- New key-agreement ciphers `enigmatic.X25519` (RFC 7748, `Size = 256`) and `enigmatic.Ecdh[256 | 384
  | 521]` (NIST curves, the same key documents as `Ecdsa`), both `Cipher & Agreeing`, where the new
  `enigmatic.Agreeing` has `agree(privateKey: Data, publicKey: Data): Data`. They are reached through
  the JDK provider's new structural members `x25519: Crypto.KeyAgreement` and `ecdh:
  Crypto.KeyAgreement` (new trait: `generateKeyPair`, `privateToPublic`, `agree`). Use them as
  `privateKey.agree(peer: PublicKey[cipher])(block: Data => result)`: the shared secret is lent to
  the block and zeroed afterwards. Additive. (#2243)
- New AEAD cipher `enigmatic.AesGcm[128 | 256]` (`Cipher & Symmetric & Authenticated`; 12-byte
  nonce, 16-byte tag), where the new `enigmatic.Authenticated` has `nonceSize`, `tagSize`,
  `seal(key, nonce, associated, plaintext): Data` and `unseal(key, nonce, associated, ciphertext):
  Optional[Data]`, reached through the JDK provider's new structural member `aesGcm: Crypto.Aead`
  (new trait: `generateKey`, `seal`, `unseal`). Use it as `symmetricKey.seal(nonce, associated,
  plaintext): Data` and `symmetricKey.unseal(nonce, associated, ciphertext): Data` raising
  `Crypto.Error` with the new reason `Crypto.Error.Reason.BadTag` on a tag failure. No `Permit` is
  needed: an AEAD cipher is not `Unauthenticated`. Additive. (#2243)
- New `enigmatic.ChaCha20` (`Cipher & Symmetric & Keystream`, where the new `enigmatic.Keystream`
  has `nonceSize` and `xor(key, nonce, counter, data): Data`), used as `symmetricKey.xor(nonce,
  counter, data)`, and `enigmatic.ChaCha20Poly1305` (RFC 8439 AEAD, `Authenticated`, used with
  `seal`/`unseal` like `AesGcm`); both via the JDK provider's new structural members `chaCha20:
  Crypto.StreamCipher` (new trait: `generateKey`, `xor`) and `chaCha20Poly1305: Crypto.Aead`.
  New `enigmatic.Poly1305.mac(key: Data, message: Data): Data`, a pure-Scala one-time
  authenticator, for constructions such as OpenSSH's `chacha20-poly1305@openssh.com` that use it
  apart from ChaCha20. Additive. (#2243)
- `enigmatic.KeyAlgorithm` gained `algorithm: Optional[Asn1]`, the type's `AlgorithmIdentifier`
  (`Unset` for DSA), and `PublicKey` gained `PublicKey.raw[cipher](bits: Data):
  Optional[PublicKey[cipher]]` and `PublicKey#raw: Optional[Data]`, converting between a key
  document and the raw key a wire protocol carries (32 bytes for X25519/Ed25519, an uncompressed
  point for EC). Additive. (#2243)
- `enigmatic.Pem.Label` gained the case `OpensshPrivateKey` (`OPENSSH PRIVATE KEY`), which
  previously parsed as `Proprietary(t"OPENSSH PRIVATE KEY")`; a match on the `Proprietary` form
  must use the new case. `Pem.aggregableIn` (the `text.read[value in Pem]` lifting over a
  `Decodable in Der`) moved to the parent trait `enigmatic.Pem2`, so that the new
  `Pem.aggregableInPem`, over a `Decodable in Pem`, outranks it; `summon`ing it by name must use
  `Pem.aggregableIn` still (inherited), so no change is expected. (#2243)
- `enigmatic` decryption paths now map provider failures through one function. `Data#decrypt`
  (`enigmatic_uncloak.scala`) is unchanged in which exceptions it maps; the streaming
  `BlockCipher#decrypt(stream, key)` previously mapped only `javax.crypto.BadPaddingException`
  (→ `Crypto.Error.Reason.BadPadding`) and `IllegalBlockSizeException` (→ `IllegalBlockSize`),
  rethrowing anything else, and now also maps `java.security.InvalidKeyException` (→ `InvalidKey`)
  and any other `java.security.GeneralSecurityException` (→ `IoFailure`) to a `Crypto.Error`, as
  the whole-value form always did; code catching those JDK exceptions around a streaming decrypt
  must handle `Crypto.Error` instead. `Crypto.javaBaseCrypto` on Scala Native, whose members all
  panicked, now forwards `random`, `aes`, `hmac`, `aesGcm`, `chaCha20`, `chaCha20Poly1305`,
  `x25519` and `ed25519` to the pure-Scala `enigmatic.SoundnessCrypto`; `rsa`, `rsaSignature`,
  `ecdsa` and the legacy ciphers still panic. (#2305)

## telekinesis

- `telekinesis.httpBackends.soundnessHttp` (the `Http.Backend` over coaxial's sockets) moved
  from the `telekinesis-jvm` module to the new `telekinesis-sockets` module, which cross-compiles
  to Scala Native (published as `telekinesis-sockets_native0.5_3`); `telekinesis-jvm` depends on
  it, so a consumer of `telekinesis-jvm` or of the `soundness` umbrella sees no change. Its
  `https` exchange is now platform-split: on the JVM it is unchanged (ALPN offering `h2` then
  `http/1.1`, driven by `Http2` or the HTTP/1.1 codec); on Scala Native it is one HTTP/1.1
  exchange over coaxial's OpenSSL `SecureEndpoint`, sent with `Connection: close`. The helpers
  `repackage` and `sequentialFetch` moved with it (`private[telekinesis]`). (#2308)

## hellenism

- `hellenism.Classpath#classloader(delegation, parent)`, `Classpath#services[service]`,
  `Classpath.Entry#javaUrl` and `internal.ClassRef#classpathEntry` are now extension methods
  (same names and signatures, defined at the top level of package `hellenism` and exported to
  `soundness`) in the JVM/Scala.js `core-jvm` source set, rather than members; call sites are
  unchanged, but a `summon`/eta-expansion by member name must use the extension. They are absent
  on Scala Native, to which `hellenism.core` now cross-compiles. `Classpath.servicesFor[service]
  (classpath, cls)` and `Classpath.Entry.apply(url: java.net.URL)` are removed from the public
  API (both were JVM plumbing: the former backs `services`, the latter `LocalClasspath`), and
  `Classpath.delegatingClassloader` moved to the private `hellenism.Loaders`. (#2310)

- `LocalClasspath(path)`, the one-argument constructor taking any path (`Abstractable across
  Paths to Text`), is now `LocalClasspath.of(path)`: with a single `Classpath.Entry.Jar` or
  `Classpath.Entry.Directory` — itself a path — `LocalClasspath(entry)` was ambiguous between
  that overload and the entries' varargs `apply`, which now resolves alone. The varargs
  `apply`, `of(classloader)` and `classpath + path` are unchanged.

## coaxial

- On Scala Native only: `Multicast` subscriptions (`coaxial.socketBackends.scalaNativeSockets`)
  send to the group once, by the kernel's default multicast route, rather than once per joined
  interface as the JVM backend does, and `Socket.Option.MulticastLoop` and `MulticastHops` are
  not applied (the kernel defaults: loopback on, one hop) — Scala Native's javalib declares
  `DatagramSocket.setOption` without implementing it. Receiving, `sendTo` and `leave` are as on
  the JVM. UDP binds on Scala Native now pass an explicit wildcard address: the javalib's
  `InetSocketAddress(port)` leaves the host name null and `bind` rejected it, so `listenUdp`
  previously threw `IllegalArgumentException` there. (#2312)

## guillotine

- `guillotine.Command#escape` now quotes an embedded single quote correctly, as `'\''`; it used
  to leave it unescaped, so a `Command` whose argument contained one re-parsed as several
  arguments. A caller that compensated by pre-escaping quotes must stop. (#2243)
- On Scala Native, `Command#pty` now runs the command on a real pseudo-terminal (the Native
  `PtyProcess`, over `posix_openpt`/`posix_spawn`/`poll`), where it previously raised
  `Exec.Error`; `OnTerminal.Job#resize`, `mode` and `mode_=` work there as on the JVM. (#2312)

## octogenarian

- New component `octogenarian.sshNative` (bundle `tool`): remote repositories over susurration,
  the native SSH client, with no `ssh` binary. `gitTransports.soundnessSsh` is the given
  `Transport` (demanding `Online`, `Socket.Backend`, `Ssh.Provider`, `Ssh.Algorithms`,
  `Ssh.HostKeys`, `Ssh.Credentials`, `Hash in Sha2[256]` and `Diagnostics`), and `SshNative()` the
  class; it accepts the same `ssh://[user@]host[:port]/path` and `[user@]host:path` URLs as
  `gitTransports.sshCommand`, which remains. One SSH connection serves every exchange with a peer,
  and stays open as long as the peer. Additive. (#2243)
- `octogenarian.SshCommand.Address` and `SshCommand.parse` moved to the `native` component as
  `octogenarian.SshAddress(user, host, port, path)` and `SshAddress.parse(url)`, so both SSH
  transports share them. Replace `SshCommand.Address` with `SshAddress` and `SshCommand.parse`
  with `SshAddress.parse`. (#2243)

## susurration

- New library `susurration` (the SSH-2 client; bundle `web`), with `susurration.Wire` (the RFC
  4251 wire encoding: `Wire.Reader(data)` with `byte`, `boolean`, `uint32`, `uint64`, `string`,
  `bytes(count)`, `text`, `mpint`, `names`, `rest`, `end`, raising `Wire.Error`; `Wire.Writer()`
  with the same fields and `data`), `susurration.KnownHosts` (`KnownHosts(text)`, `lookup(host,
  port)`, `verify(host, port, keyType, keyBlob): KnownHosts.Verdict` of `Known`, `Unknown`,
  `Changed` or `Revoked`; patterns, negation, `[host]:port`, hashed entries and markers) and
  `susurration.SshConfig` (`SshConfig(text).resolve(host): SshConfig.Resolution(hostName, user,
  port, identityFiles)`; `Host` blocks with `HostName`, `User`, `Port` and `IdentityFile`).
  Additive. (#2243)
- `susurration.Transport(duplex: Duplex, hostname: Text, port: Int)(using Ssh.Provider,
  Ssh.Algorithms, Ssh.HostKeys, Hash in Sha2[256])` is the SSH transport layer (RFC 4253) over a
  coaxial `Duplex`: `connect()` does the identification exchange and key exchange (`curve25519-
  sha256`, `ecdh-sha2-nistp256`; host keys `ssh-ed25519`, `ecdsa-sha2-nistp256`, `rsa-sha2-512`,
  `rsa-sha2-256`; ciphers `chacha20-poly1305@openssh.com`, `aes256-gcm@openssh.com`,
  `aes128-gcm@openssh.com`), then `send(payload)`, `receive(): Data`, `expect(message)`,
  `service(name)` and `disconnect()` move encrypted packets; `sessionId`, `negotiated` and
  `serverVersion` describe the session. `susurration.Ssh` holds `Ssh.Version`, `Ssh.Message`
  numbers, `Ssh.Algorithms` (the preference lists, with a `default` given), `Ssh.HostKeys` (the
  host-key policy: a given from a `KnownHosts`, `trustOnFirstUse(known)`, `insecurelyAcceptAll`)
  and `Ssh.Error` (`Malformed`, `Unexpected`, `NoCommonAlgorithm`, `HostKeyRejected`,
  `BadSignature`, `Disconnected`, `ClosedConnection`, `Integrity`, `ServiceRefused`). Re-keying is
  not yet performed. Additive. (#2243)
- `Transport#authenticate(user: Text, signers: List[Signer])` performs public-key authentication
  (RFC 4252) with the first accepted signer, requesting `ssh-userauth` itself; it raises
  `Ssh.Error` with the new reason `Unauthenticated(methods)`, or `Agent(detail)` for an agent
  failure. `susurration.Signer` (`algorithm`, `blob`, `sign(data): Data`, the full signature blob)
  is made with `Signer(key: PrivateKey[cipher]^)` for a cipher with a `susurration.Identity`
  instance (`Ed25519`, `Ecdsa[256|384|521]`, `Rsa[2048|3072|4096]`, which sign as `ssh-ed25519`,
  `ecdsa-sha2-nistp*` and `rsa-sha2-256`), or obtained from an ssh-agent with
  `Agent(socketPath).identities()`, which signs through the agent. `Transport#receive` now raises
  `Unexpected(3)` on `SSH_MSG_UNIMPLEMENTED` rather than skipping it. Additive. (#2243)
- `enigmatic.OpenSsh.blob(key: PublicKey[cipher]): Optional[Data]` is the wire form of a public
  key, which `OpenSsh.line` now builds on. Additive. (#2243)
- The umbrella reaches susurration's classes as members of `Ssh`: `Ssh.Transport`,
  `Ssh.Channel`, `Ssh.Session`, `Ssh.Signer`, `Ssh.Identity` and `Ssh.Agent` (type aliases and
  companion values), since other libraries export `Transport`, `Channel`, `Session`, `Agent` and
  `Identity`; within `package susurration` the bare names are unchanged. `Ssh.Credentials`
  (`user(host): Optional[Text]`, `signers(host, user): List[Signer]`; `Ssh.Credentials(signers*)`
  and `Ssh.Credentials.agent(socket)`) supplies identities to a transport given only a URL.
  Additive. (#2243)
- The connection protocol (RFC 4254): `susurration.Session(transport)` opens session channels —
  `exec(command, input = Data(), environment = Nil): Session.Result(stdout, stderr, status)` runs
  a command to completion, `channel(block: Channel => result)` lends a `susurration.Channel`
  (`env`, `exec`, `write`, `eof`, `next(): Optional[Channel.Event]`, `stdout(): Chain[Data]`
  lazily, `stderr`, `exitStatus`, `close`), and `close()` disconnects. `Ssh.Endpoint(host, port,
  user, signers)` is `Sessional to Session^` (given `Online`, `Socket.Backend`, the provider,
  algorithms, host-key policy, `Hash in Sha2[256]`, `Tactic[Ssh.Error]` and `Diagnostics`), so
  `endpoint.session: ssh ?=> ssh.exec(t"uname")` connects, verifies, authenticates and runs;
  `Endpoint#resolved(config: SshConfig)` applies `~/.ssh/config`. `exec` on both takes any
  `command: Ssh.Invocable` — a `Text` run as written, or a guillotine `Command` quoted argument
  by argument (`ssh.exec(sh"git log -1 $$branch")`); susurration now depends on guillotine. New reasons `ChannelRefused`
  and `RequestRefused`. `Transport`, `Session` and `Channel` are plain classes driven by one
  thread (not `caps.Mutable`): their methods are no longer `update` methods, so a `Transport`
  needs no `^`. Additive. (#2243)

## wisteria

- The `field` type that `wisteria.ProductDerivation.Methods#build`, `#construct`, `#contexts`
  and `#fields` bind for their lambdas (and `constructMonadic` for the constructed tuple) now
  keeps the field's capture annotation: a field declared `values: Array[Long]^{}` binds `field`
  as `Array[Long]^{}` where it previously bound the bare `Array[Long]`. A derived typeclass
  instance over a product with a frozen-array field (`Array[element]^{}`) therefore now
  compiles in a capture-checked (`-language:experimental.captureChecking` with separation
  checking) module, where it previously failed with a capture error or crashed the checker; the
  "known limitation" recorded under `## locomotion` in `0.72.0.md` (#2248) no longer applies.
  Derivations over fields with no capture annotation are unchanged. (#2292)

## caesura

- `import codecs.direct` now also selects the direct DSV parser: under it, `read[Foo in Dsv]`,
  `read[List[Foo] in Dsv]` and `rowsOf[Foo]` resolve `Foo is caesura.Dsv.Parsable` for every
  product type `Foo` through the new blanket given `caesura.Dsv.Parsable2#generated` (equivalent
  to `Dsv.Parsable.derived[Foo]`), where previously only a type with a `Dsv.Parsable` instance of
  its own took that path and every other product was decoded through `Decodable in Dsv`. Results
  are the same, but the direct parser reads each field through `Dsv.Field` (any `Decodable in
  Text`, `Optional` of one, or a product of such fields), so a product with a field whose only
  instance is `Decodable in Dsv` now fails to compile under `import codecs.direct`; declare no
  mode, or `import codecs.derived`, for such a type. `import codecs.derived` now overrides a
  `Dsv.Parsable` in scope for `read[Foo in Dsv]` (not for `read[List[Foo] in Dsv]`, which has no
  derived counterpart), as it does for the other formats. (#2251)

## caduceus

- `couriers.resendCourier` now declares its result as `Courier { type Result = Resend.Receipt }`
  rather than a bare `Courier`, so `courier.send(…)` under it is a `Resend.Receipt` at the use
  site, where it was previously inferred as the opaque `?.Result` and could not be ascribed.

## frontier

- The explanation of a missing given (`explainMissingContext`) is now bounded: a chain of
  candidates deeper than six, or more than 256 implicit searches in one explanation, is
  reported as missing rather than followed. An explanation in a large scope — a REPL session
  with every import of a long tutorial, say — previously ran for hours. The report is the same
  for every chain within the bound.

- Changed output formatting of the catch-all's tree (`frontier.context.explainMissingContext`,
  `soundness.explainMissingContext`): a `scala.util.NotGiven[X]` requirement — a `using`
  parameter of a tried candidate or of a proposed classpath given, including the parameter of a
  `proscenium.prohibits` given — now renders as `⊘ prohibits X` instead of
  `✗ requires NotGiven[X]`; when an `X` is in scope the node has one child, `✓ found X (<given>)`,
  naming the given that supplied it, and when none is it has no child and the label `(absent)`.
  A candidate of context-function type (`Choice prohibits Policy`, i.e.
  `NotGiven[Policy] ?=> Choice`) is now listed as `▪ candidate <given>`, where it was
  `▪ candidate ContextFunction1.apply` requiring `ContextFunction1.scala$ContextFunction1$$T1`.
  A top-level `summon[NotGiven[X]]` is unchanged (no tree; the compiler's own message).
  Code that matches on the message text for `requires` and `NotGiven` must be updated.
  (#2307)

## hyperbole

- Changed dependency of `hyperbole.tasty` (`Tasty.parse`, `Tasty.File`, `Tasty.Definition`): it
  now reads TASTy through `org.scala-lang:tasty-core_3` — a runtime dependency of the module, so
  it is resolved transitively — instead of the compiler's `TastyUnpickler`, and the compiler
  (`scala3-compiler_3`) is no longer needed on the runtime classpath to call `Tasty.parse`. Code
  that added the compiler to its classpath only for this can drop it. No API change: the model
  types and `Tasty.parse(data: Data): Optional[Tasty.File]` are unchanged. Names derived by the
  compiler render as before (`prefix.name`, `name$1`, `method$default$2`, `super$name`, …),
  except signed names, which now render as the name they sign rather than
  `name[with sig …]`; a stack-frame resolution never saw those, since the reader only reads a
  name at a definition, a package or the source-file attribute.
- New: `hyperbole.tasty` is published for Scala.js (`hyperbole-tasty_sjs1_3`) and Scala Native
  (`hyperbole-tasty_native0.5_3`) from this release, so `Tasty.parse` can run in a browser, under
  Wasm or in a native binary; it needs Proscala 1.0.4, whose `tasty-core_sjs1_3` and
  `tasty-core_native0.5_3` it depends on. `hyperbole.core` and `hyperbole.stacks` stay JVM-only.

## tasseomancy

- New: `Doughnut()`, a chart kind drawing an acyclicity `Dag[node]` as concentric bands, one per
  rank of the graph from the nodes depending on nothing outward, each node a sector of its band
  proportional to its size and filled clockwise as far as it is complete. It needs the new
  typeclasses `node is Sized` (`size(node): Double`) and `node is Progressive`
  (`completion(node): Double`, from `0.0` to `1.0`), both exported from `soundness`; a doughnut
  is revised with a new `Dag` of progressed nodes, and its fit survives any graph of the same
  shape and sizes. The drawing's parts are `rank-N` groups of `sector-N` and `sector-N-rest`
  paths; `Doughnut.Style` adds `hole` (shared with `Pie.Style`), `sectorGap`, `bandGap`,
  `shade(x, y, base)` (a sector's colour from its position), `sector(...)` and `remainder(...)`,
  and `Chart.Standard` has the new fields `sectorGap: Double
  = 2.0` and `bandGap: Double = 2.0` (both in pixels) and extends `Doughnut.Style`. `tasseomancy.core` now
  depends on `acyclicity.core`, which a consumer declaring Soundness modules individually must
  add. (#2309)
