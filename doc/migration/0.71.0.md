# Changes since 0.70.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.70.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## anthology

- `anthology.Format` gains an abstract member `kind: anthology.Format.Kind` (new enum: `Source`,
  `Ir`, `Application`), implemented as a `final def` by `Format.Source`, `Format.Ir` and
  `Format.Application`, and `final override` definitions of `equals` and `hashCode`: two formats
  are equal when their `kind`s and `id`s are equal. A class extending `Format` other than through
  one of the three tier traits must define `kind`; one overriding `equals` or `hashCode` no longer
  compiles; and a case class extending `Format` no longer has a synthesized structural `equals`.
  Two formats of one kind with the same `id` are now equal even if their other members differ, so
  a format whose parameters distinguish nodes must encode them in its `id` (every built-in format
  already does). (#2166)

## apoplexy

- `apoplexy.OpenApi.json(yaml: Yaml): Json` removed. The translation is now the top-level given
  `apoplexy.yamlEncodableInJson: Yaml is Encodable in Json` (not exported by `soundness`), so
  write `yaml.in[Json]` with `import apoplexy.yamlEncodableInJson` in scope for
  `OpenApi.json(yaml)`. The output is unchanged. (#2176)

## archimedes

- `archimedes.Ergo.Error.Reason.BadOpener(char: Text)`, `Unclosed(expected: Text)` and
  `MissingBody(char: Text)` now take a `Char` in place of the single-character `Text`:
  `BadOpener(char: Char)`, `Unclosed(expected: Char)`, `MissingBody(char: Char)`. The rendered
  messages are unchanged. Patterns binding the field and comparing it with a `Text` compare with
  a `Char` instead. (#2167)
- `archimedes.Mathml#htmlAttributes: List[(Text, Optional[Text])]` removed. Use `attributes`,
  whose `List[(Text, Text)]` conforms wherever `(Text, Optional[Text])` pairs are expected (for
  example `honeycomb.Attributes(node.attributes*)`). (#2167)
- `archimedes.Math#xml: Xml` and `archimedes.Mathml#xml: Xml` removed in favour of the givens
  `Math.encodableInXml: Math is Encodable in Xml` and `Mathml.encodable: [node <: Mathml] =>
  node is Encodable in Xml`. Write `math.in[Xml]` for `math.xml` and `element.in[Xml]` for
  `element.xml`; use `in[Xml]`, not `encode`, on a `Math`, which also has an `Encodable in
  Math`. The output is unchanged. (#2176)
- `archimedes.Math#html: Html of "math"` and `archimedes.Mathml#html: Html of "#foreign"`
  removed. `math.html` and `element.html` still compile unchanged through honeycomb's `html`
  extension (in scope with `import soundness.*` or `import honeycomb.*`), resolved by the
  existing `Math.renderable` and the new `Mathml.renderable: [node <: Mathml] => node is
  Renderable { type Form = "#foreign" }`. (#2176)


## aviation

- `aviation.Calendar#Mensual` now has a `Showable` context bound (`type Mensual: Showable`), and
  `Calendar#monthName(month: Mensual): Text` now renders `month.show` where it rendered
  `month.toString.tt`. A calendar defined outside aviation must have a `Showable` for its month
  type in scope where the calendar is defined; an `enum` month already has one through
  `spectacular.Showable.enumeration`, which renders the case name as before. (#2173)
- `aviation.AlexandrianCalendar` changed from `abstract class AlexandrianCalendar()` to
  `trait AlexandrianCalendar`. Rewrite `extends AlexandrianCalendar()` as
  `extends AlexandrianCalendar`. (#2173)
- The givens `aviation.CopticMonth.showable`, `aviation.EthiopianMonth.showable`,
  `aviation.FrenchRepublicanMonth.showable`, `aviation.IndianMonth.showable` and
  `aviation.PersianMonth.showable` removed; `spectacular.Showable.enumeration` resolves in their
  place with the same output, so only code naming one of these givens explicitly must change.
  (#2173)

## beneficence

- The compiler plugin (`beneficence-plugin`) writes a new resource directory,
  `META-INF/probably/tests`, into the output of every compilation which has `probably.Suite` and
  `probably.Testable` on its classpath: one file per source file which declares a suite or a
  test, named `<source file name>-<12 hex digits of the SHA-256 of its path>`. The format is
  documented in `beneficence.TestsIndex`. `META-INF/services/probably.Suite` is unchanged. A
  build which packages compiler output by an explicit list of resource paths must include the
  new directory for a host (fume) to list its tests without running them; no merge rule is
  needed, since no two modules write the same entry. (#2169)

## bitumen

- `bitumen.UnixMode#bytes: Data`, `bitumen.UnixUser#bytes: Data` and `bitumen.UnixGroup#bytes:
  Data` removed. They produced the USTAR header field (seven zero-padded octal ASCII digits), a
  format of tar rather than of the types, and are now private to `Tar.Header`. Code that needs
  the field writes `value.octal.pad(7, Rtl, '0').in[Data]` from `mode.int`, `user.value` or
  `group.value`. (#2176)

## enigmatic

- `enigmatic.Cose#bytes: Data` removed in favour of the given `Cose.encodable: [cose <: Cose] =>
  cose is Encodable in Data`. Write `cose.in[Data]` for `cose.bytes`; the wire form is
  unchanged. (#2176)

## ethereal

- `ethereal.DaemonService` renamed to `ethereal.Resident` (also exported as `soundness.Resident`),
  and its type parameter replaced by a type member: `case class DaemonService[bus <:
  Matchable](…)` is now `abstract class Resident(…)` with `type Transport <: Matchable`, the type
  of the messages its clients exchange. Write `DaemonService[X]` as `Resident over X`
  (`prepositional.over`), and `DaemonService[?]` as `Resident`. The constructor no longer takes
  `deliver: bus => Unit` or `bus: Chain[bus]`; `bus: Chain[Transport]` and `broadcast(message:
  Transport): Unit` are abstract members, implemented by the daemon. Being no longer a case class,
  it has no `copy`, `unapply`, or structural `equals`/`hashCode`; its other constructor parameters
  remain public `val`s, with the same names. (#2163)
- `ethereal.service[bus <: Matchable](using DaemonService[bus]): DaemonService[bus]^{service}`
  (also `soundness.service`) renamed to `ethereal.resident[bus <: Matchable](using Resident over
  bus): (Resident over bus)^{resident}` (also `soundness.resident`); `service` removed. Rewrite
  every `service.…` inside a `cli` block as `resident.…`. The context function taken by
  `ethereal.cli[bus]` now provides `Resident over bus` in place of `DaemonService[bus]`. (#2163)
- `ethereal.Upgrade.apply[source](source: source): Nothing raises Upgrade.Error` and
  `Upgrade.applyBytes(bytes: Data): Nothing raises Upgrade.Error` removed; use
  `Upgrade.stage[source](source: source): Unit raises Upgrade.Error`, which takes the same
  `Readable to Data` source. It writes the candidate as `<data>/<name>/.pending` and *returns*:
  it no longer starts a launcher or exits the JVM, and the launcher applies the upgrade at the
  start of the command's next invocation. Code that relied on `Upgrade(…)` not returning (for
  example as the last expression of a `Nothing`-typed method) must now return normally, and
  should tell the user that the upgrade takes effect the next time the command is run. (#2171)
- `ethereal.Upgrade.Error.Reason.CannotRespawnLauncher` removed, and
  `Upgrade.Error.Reason.CannotResolveLauncher` renamed to `CannotResolveName` (still `SN-631.3`,
  raised when the daemon was not given its name by a launcher). Matches on either update
  accordingly. (#2171)
- `ethereal.Upgrade` gains `pending: Boolean` (whether a staged upgrade awaits the next
  invocation), `outcome: Optional[Upgrade.Outcome]` (what the launcher last did with one, read
  from `<data>/<name>/.upgrade-result`), `acknowledge(): Unit` (clears that outcome) and
  `enabled: Boolean` (from the `ethereal.upgradable` property; false for an executable built
  without a release key and application id). `Upgrade.Outcome(result: Outcome.Result,
  candidate: Long, previous: Long, time: Long)` has `when[instant]`, an `Instant` through
  `Instantiable`; `Outcome.Result` is an enum of `Applied`, `Disabled`, `NoRecord`,
  `WrongApplication`, `BadSignature`, `NotNewer` and `SwapFailed`. Additive. (#2171)
- `ethereal.Resident` gains `buildId: Long`, the running executable's build id (the `build.id`
  property, or zero). The daemon now reads `build.id`, and the `build.id` classpath resource that
  stands in for it, as a 64-bit `Long` rather than an `Int`. Additive. (#2171)
- The `ethereal-sign` Rust crate (`lib/ethereal/Cargo.toml`, `src/sign`) removed: it signed a
  record format (`ETHRCFG` v2) which no current launcher reads. Sign with `xek` 1.1.0 or later
  (`xek keygen --out <prefix>`, `xek sign --key <seed> --in <binary> --out <signed>`; Java 24 or
  later). Executables need xek 1.1.0 or later (`ETHRCFG` v4) to be upgradable, and are built with
  `--app-id <identifier>` as well as `--public-key`. From xek 1.1.0, every `xek` command line
  begins with a subcommand: write `xek build [options] <app.jar> [<output>]` where
  `xek [options] <app.jar> [<output>]` was written, including the usage line the daemon prints
  when it is run without a launcher. (#2171)

## exoskeleton

- `exoskeleton.Enclave` (`exoskeleton-rig`) now finds the builder it packages with in the
  environment variable `$XEK` instead of `$XEQ`, and defaults to `dist/xek` instead of
  `dist/xeq`. A test environment that set `$XEQ`, or fetched the builder into `dist/xeq`, sets
  `$XEK`, or fetches it into `dist/xek`, instead; `$XEQ` is no longer read. (#2157)
- `exoskeleton.Enclave`'s `buildId` parameter is now `Optional[Long]` (was `Optional[Int]`); an
  `Int` argument is widened by the compiler. `Enclave` also takes `releaseKey: Optional[Path on
  Linux]`, `recoveryKey: Optional[Path on Linux]` and `appId: Optional[Text]`, all defaulting to
  `Unset`, passed to `xek` as `--public-key`, `--recovery-key` and `--app-id`; positional
  arguments after `buildId` are unaffected, since these follow it. `Enclave.keygen(prefix)` and
  `Enclave.Launcher#sign(seed, out, foreign = false)` run `xek keygen` and `xek sign` (Java 24 or
  later). `Enclave` now runs `xek build`, so it needs a builder from xek 1.1.0 or later in `$XEK`
  or `dist/xek`. A failure of `xek` to package the
  executable now panics with a message, where it raised a `NotImplementedError`. (#2171)
- A `Subcommand` with `hidden = true` is unchanged in matching, completion and help, but where
  *every* subcommand candidate at a position is hidden, completion now offers the flags as well,
  rather than (in bash, fish and PowerShell) nothing. (#2171)

## facsimile

- `facsimile.Print.baseFont(standard: Pdf.Font.Standard): Text` removed. The PostScript name is
  now a field of the enum, `facsimile.Pdf.Font.Standard#baseFont: Text`, so write
  `standard.baseFont` for `Print.baseFont(standard)`; the names are unchanged. (#2173)

## frontier

- With `frontier.context.explainMissingContext` or `soundness.explainMissingContext` in scope (the
  latter is brought in by `import soundness.*`), `scala.util.NotGiven[X]` previously resolved
  whether or not an instance of `X` was available; it now resolves if and only if the search for
  `X` fails, as specified. The catch-all, when tried as a candidate for a `NotGiven[X]` target,
  now returns `scala.util.NotGiven.value` instead of aborting, which the compiler's per-candidate
  negation turns into a failure, so `NotGiven`'s own instances decide. Consequences for existing
  code compiled under the umbrella: a given guarded by a `NotGiven` whose subject is present is no
  longer eligible, so searches that reported two ambiguous alternatives (one guarded, one not)
  now select the unguarded one, e.g. `aviation.Timespan.dateMonths` over `dateRegular` for
  `date + n*Month` under a `Calendar`, and `escapade.Teletype.add` no longer applies where
  `Teletype is Textual` is in scope; code that compiled only because such a guard was defeated
  (e.g. `summon[NotGiven[Ordering[Int]]]`) now fails with a missing-given error. (#2123, #1955)

## graffiti

- `graffiti.Archetype#html: Html of "html"` (a `final def`) removed in favour of the given
  `Archetype.renderable: [page <: Archetype] => page is Renderable in "html"`. `page.html`
  compiles unchanged through honeycomb's `html` extension (in scope with `import soundness.*`
  or `import honeycomb.*`), and `Archetype#document` is unchanged. A page that defines its own
  `html` member would now shadow the extension rather than fail to compile. (#2176)

## honeycomb

- `honeycomb.Node`, `honeycomb.Element`, `honeycomb.Comment`, `honeycomb.Doctype` and
  `honeycomb.Fragment` moved into the `Html` companion, with their companion objects: they are
  now `honeycomb.Html.Node`, `honeycomb.Html.Element`, `honeycomb.Html.Comment`,
  `honeycomb.Html.Doctype` and `honeycomb.Html.Fragment` (so `Element.foreign` is
  `Html.Element.foreign`). Each is removed from the `soundness` umbrella export, so the bare
  names `Node`, `Element`, `Comment`, `Doctype` and `Fragment` no longer resolve through
  `import soundness.*` or `import honeycomb.*`; write `Html.Element`, `Html.Fragment` and so on,
  in types, constructor calls and patterns (`case Html.Element(label, attributes, children, _)`).
  Behaviour unchanged. (#2167)
- `honeycomb.TextNode` renamed to `honeycomb.Html.Text`, and `TextNode.foreign` to
  `Html.Text.foreign`; `TextNode` removed, including from the `soundness` umbrella export.
  Behaviour unchanged. Inside a scope that imports `Html.*`, the bare name `Text` now means this
  node type rather than `anticipation.Text`; such imports should be replaced by qualified
  references. (#2167)
- `honeycomb.Honeycomb` (also exported as `soundness.Honeycomb`) removed. Its members,
  `extractor`, `interpolator` and `attributes`, were unused duplicates of the macro
  implementations in `honeycomb.internal`, which the `h""` interpolator and tag application
  call; no replacement is needed. (#2173)

## jacinta

- `jacinta.Json.apply` gains overloads `apply(value: Int)`, `apply(value: Short)`,
  `apply(value: Byte)`, `apply(value: Float)`, `apply(value: Long)` and `apply(value: Double)`
  beside `apply(value: Any)`. `Json(i)` for an `Int`, `Short` or `Byte` now holds that integer
  (stored as a `Long`), where it previously held the `Int` raw, which the AST reads as a packed

## probably

- `probably.Suite` has a type parameter and a second constructor:
  `abstract class Suite(suiteName: fulminate.Message)` is now
  `abstract class Suite[topic <: Label]`, with `type Topic = topic` and the public constructors
  `Suite(title: Message)(using Suite.Derivation[topic])` and `Suite(id: topic, title: Message)`.
  `object Tests extends Suite(m"Parser tests")` compiles unchanged, `topic` being inferred as
  `probably.Derived` (new, an opaque `Label`); `Suite("parser", m"Parser tests")` infers the
  literal type `"parser"`. The type `Suite` alone no longer compiles; write `Suite[?]`. (#2169)
- Every suite has an id (`Testable#key: Optional[Text]`, new; `Test.Id#key`, new, a final
  field of the case class, default `Unset`): the string given to `Suite(id, title)`, or
  `Suite.derive(title.text)` — the title's letters and digits in lower case, each run of other
  characters as one `-`, none leading or trailing, `suite` if empty (`m"Honeycomb Tests"` gives
  `honeycomb-tests`). With the beneficence plugin, a given id which does not match
  `[A-Za-z_][A-Za-z0-9_-]*` is a compile error. Observable effects: `TestEvent.Ref#path` of a
  suite and of everything in it now begins with the suite's id where it began with its title;
  `TestEvent.Ref#moniker` of a suite is its id where it was `Unset`; a selection term equal to
  a suite's id, or a glob matching it, admits everything in the suite, and a path glob must
  begin with the id (`honeycomb-tests/**`), though a glob matching the title alone
  (`'Honeycomb Tests'`) still admits the suite. (#2169)
- `probably.Testable` has an abstract type member, `type Topic`, and the contextual value which
  declarations take is a `Testable of topic` (`prepositional.of`) whose topic is a `Label`: the
  literal id of the `Suite` it belongs to, `probably.Derived` for a suite without a given id,
  or `probably.Impromptu` (new, an opaque `Label`). `Suite#testable` is now `given testable: Testable of topic`. A `given` or `using`
  parameter of the bare type `Testable` no longer satisfies `test`, `suite` or sedentary's
  declarations, and fails with "a test must be declared for a Suite …". A method which declares
  tests for a suite must take `(using Testable of "<that suite's id>")` in place of
  `(using Testable)`, the suite being given an id for the purpose (`Suite("<id>", title)`); a
  method shared by several suites, or declaring tests for a suite with a derived id, takes a
  type parameter, `[topic <: Label](using Testable of topic)`. (#2169)
- A method with a `using` parameter of the bare type `Testable`, compiled with the beneficence
  plugin where `probably.Suite` is on the classpath, is now a compile error ("this Testable has
  no topic …"), whether or not it declares a test. Without the plugin such a method compiles
  if another `Testable` with a topic is in scope where its tests are declared (the enclosing
  `Suite`'s, typically), and its tests are then declared at THAT position — the root of the
  suite — and not, as before, wherever the method was called from. Every `(using Testable)`
  must be audited. (#2169)
- `probably.test` (both overloads): the unused type parameter `report` is replaced by
  `topic <: Label`, and the parameter `suite: Testable` is now `suite: Testable of topic`.
  `probably.suite` (both overloads) is now
  `suite[topic <: Label, report](name)(using suite: Testable of topic, runner: Runner[report],
  codepoint: Codepoint)(block: (Testable of topic) ?=> Unit)`: it gains the type parameter
  `topic` before `report` and the `Codepoint` parameter, and its block receives a
  `Testable of topic`. A group's `TestEvent.Ref` (`SuiteStarted`, `SuiteEnded`) now carries the
  file and line of the `suite(…)` call, where it carried a position inside Probably's own source. (#2169)
- `probably.Runner#suite(suite: Testable, block: Testable ?=> Unit): Unit` is now
  `suite[topic](suite: Testable of topic, block: (Testable of topic) ?=> Unit): Unit`.
  Implementations of `Runner` must change the signature to match. (#2169)
- The constructor of `probably.Testable` is now `private[probably]`, and its second parameter
  is `parents: List[Testable]` (not a member) where it was `val parent: Optional[Testable]`;
  `Testable#parent: Optional[Testable]` remains, as a method. Construct one with
  `Testable.of[topic](name: Message, parent: Optional[Testable] = Unset, moniker:
  Optional[Name[Probing]] = Unset, key: Optional[Text] = Unset)(using Codepoint): Testable of
  topic` (new). (#2169)
- A test declared where the contextual `Testable` is a suite's, but which is not one of that
  suite's tests — a fixture declared inside another test's body to exercise a `Runner` or a
  `Selection` of the program's own, for instance — still compiles, but is now recorded in the
  index of tests the beneficence plugin writes. Wrap such declarations in `probably.impromptu`
  (new: `impromptu[result](using parent: Testable = Testable.detached)(block: (Testable of
  Impromptu) ?=> result): result`, also `soundness.impromptu`), which keeps the test at the same
  position in the hierarchy and leaves it out of the index. (#2169)
- `probably.Test.Id#id`, the six hex digits a test or suite is known by (and `TestEvent.Ref#id`,
  which carries it), is computed differently, so EVERY id changes: it is now the low 24 bits of
  `h ^ name.text.s.hashCode`, where `h` is the sum of `name.text.s.hashCode` over the suites the
  test is within, and `Testable#hashCode` is that sum including its own name. It was computed
  from `Message#hashCode`, which depends on the message's structure and not only its text.
  Stored ids (in selections, scripts, charts keyed by id) no longer match; monikers and names
  are unaffected. (#2169)

## stratiform

- `stratiform.layer` (`case class layer(name: Text) extends StaticAnnotation`, also exported as
  `soundness.layer`) removed. Its replacement is `stratiform.assign` (`final class assign(layer:
  Tel.Layer[?]) extends StaticAnnotation`; `soundness.assign` is a type alias of it, leaving the
  term `soundness.assign` to anamnesis), which names a layer by a
  singleton object rather than by text. Rewrite `@layer(t"foo")` on a field as `@assign(foo)`,
  declaring once, at the top level or in an object, `object foo extends Tel.Layer("foo")` (the
  same name); fields sharing a layer name share the one object. The derived schema is unchanged.
  The argument of `@assign` must be a reference to such an object, whose name is a string
  literal; anything else is now a compile error at the annotation. (#2165)
- New `stratiform.Tel.Layer[name <: String & Singleton](val name: name)`, an open class a layer
  object extends, and `stratiform.Tel.Name[layer <: Tel.Layer[?]]`, the match type giving a
  layer's name from its type. New annotation `stratiform.retract` (`final class retract(layer:
  Tel.Layer[?]) extends StaticAnnotation`, also `soundness.retract`), for a case of a sum. Not
  required by existing code. (#2165)
- Layer composition (`Tels.Layers.compose`, `Tels.Layers.composeComponents`, and acceptance
  serving and reading) no longer rejects a layer's `exclude` of a variant which the base
  `select` declares but an earlier layer has already excluded: it is a no-op. Previously that
  raised `Tel.Error` with reason `ExcludeMissingVariant` (E211). An `exclude` of a variant the
  base `select` never declared still raises it. (#2165)
- `fulfil(acceptance, codecs)` on a value leaves out of its composition any offered layer whose
  `select` excludes a variant keyword that the value's encoded document uses anywhere, where it
  previously offered every layer (and failed to serve such a value). The served
  `Tel.Acceptance.Served#hashes` may therefore omit such layers. (#2165)
- `stratiform.Tels.Reconstructor.fromTel(tel: Tel): Tels raises Tel.Error` removed in favour of
  the given `Tel.telsDecodable: Tels is Tel.Decodable`. Write `tel.as[Tels]` for
  `Tels.Reconstructor.fromTel(tel)`; it raises `Tel.Error` as before. `Tels.Reconstructor` remains
  for `equivalent`. (#2176)
- `stratiform.Tels.SemanticReconstructor.fromElement(root: Tel.Element): Tels raises Tel.Error`
  removed in favour of the given `Tels.elementDecodable: Tels is Decodable in Tel.Element`.
  Write `element.as[Tels]` for `Tels.SemanticReconstructor.fromElement(element)`; a value typed
  as the subtype `Tel.Element.Node` must be ascribed, `(node: Tel.Element).as[Tels]`, since
  `Decodable`'s form is exact. (#2176)

## telekinesis

- `telekinesis.Http2.SettingId.fromId(id: Int): Optional[SettingId]` removed; it was unused.
  Match on the enum's `id` field instead. (#2176)

## xylophone

- The extension `xylophone.Attributes#toList: scala.collection.immutable.List[(Text, Text)]` is
  removed. `Attributes` is now `Traversable by (Text, Text)`, in document order, so write
  `attributes.to[List]`, which yields a `proscenium.List[(Text, Text)]`. Where a stdlib
  `List` is still needed, write `attributes.iterator.toList`. (#2167)
- `xylophone.Node`, `xylophone.Element`, `xylophone.Comment`, `xylophone.Doctype`,
  `xylophone.Cdata`, `xylophone.ProcessingInstruction`, `xylophone.Header` and
  `xylophone.Fragment` moved into the `Xml` companion, with their companion objects: they are now
  `xylophone.Xml.Node`, `xylophone.Xml.Element`, `xylophone.Xml.Comment`, `xylophone.Xml.Doctype`,
  `xylophone.Xml.Cdata`, `xylophone.Xml.ProcessingInstruction`, `xylophone.Xml.Header` and
  `xylophone.Xml.Fragment`. The bare names no longer resolve through `import xylophone.*`; write
  `Xml.Element`, `Xml.Fragment` and so on, in types, constructor calls and patterns
  (`case Xml.Element(label, attributes, children)`). Behaviour unchanged. (#2167)
- `xylophone.TextNode` renamed to `xylophone.Xml.Text`; `TextNode` removed. Behaviour unchanged.
  Inside a scope that imports `Xml.*`, the bare name `Text` now means this node type rather than
  `anticipation.Text`; such imports should be replaced by qualified references. (#2167)
