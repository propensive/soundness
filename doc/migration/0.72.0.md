# Changes since 0.71.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.71.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## build

- The tools in `etc/tools` are flair 0.6.0 (the compiler plugin Soundness is compiled with),
  fume 0.7.0 (the test runner) and flame 0.6.0, each built against Soundness 0.71.0 and
  Pyrocosm 0.6.0 (were flair 0.5.0, fume 0.6.0 and flame 0.5.0). No library's API changes.
- `etc/xek.tsv` pins xek 1.3.0 (was 1.2.0), and `etc/ci/xek-fetch.sh` fetches only releases
  tagged with the bare version, from 1.0.0; a pin naming an `xek-0.x` or `xeq-0.x` builder no
  longer resolves. No library's API changes.

## syndesis

- `syndesis.Discovery.Backend#advertise(service: Discovery.Service, description:
  Discovery.Description)(using Monitor^, Probate^, Tactic[Discovery.Error])` now returns
  `Discovery.Advertising` (new trait, one member `def instance: Discovery.Instance`) instead of
  `Discovery.Instance`, and `Discovery.Backend#withdraw` takes `(advertising:
  Discovery.Advertising)(using Monitor^)` instead of `(instance: Discovery.Instance)(using
  Monitor^)`. A `Backend` implementation must return a handle and accept it back; a caller using
  the seam directly reads the name as `advertising.instance`. The loan
  `service.advertise(description) { … }` is unchanged. (#2186)
- `syndesis.Discovery.Advertisement`'s constructor takes `(advertising: Discovery.Advertising)`
  instead of `(val instance: Discovery.Instance)`; `instance` is now a `def` that reads the
  backend's current name. Its value may change during the block: after RFC 6762 §9 re-probing,
  `Mdns.Responder` renames an established instance (`Gondor` → `Gondor (2)`) when another host
  is found to hold its name, where previously such a response was only cached. Code that reads
  `instance` once and reuses it must re-read it when the name matters. (#2186)
- `syndesis.Mdns.Transport` replaces `def receive(): Packet raises Socket.Error` with `def
  inlets: List[Mdns.Transport.Inlet]`, where `Mdns.Transport.Inlet` (new trait) has `def
  receive(): Packet raises Socket.Error`; `Mdns.Transport.sockets` now joins `ff02::fb` as well
  as `224.0.0.251` (one inlet each) on interfaces with an address of that family, and fails only
  if neither group can be joined. A `Transport` implementation with one socket extends `Inlet` too and
  returns `List(this)`. `Mdns.Transport.Bus#join` now returns `Transport & Transport.Inlet`
  (previously `Transport`), so `receive()` on a bus member is unchanged. (#2186)
- `syndesis.Discovery.Backend#advertise`, `#browse` and `#resolve` take an additional using
  parameter `(Discovery.Activity is Loggable)^` in their final `using` clause (after
  `Tactic[Discovery.Error]`), and `#withdraw` takes `(using Monitor^, (Discovery.Activity is
  Loggable)^)` instead of `(using Monitor^)`; `Discovery.Activity` is a new enum (`Probing`,
  `Yielded`, `Conflicted`, `Claimed`, `Withdrawn`, `Browsing`, `Resolved`) with a `Communicable`
  given. The loans `service.advertise(description) { … }`, `service.browse { … }` and
  `instance.resolve(timeout)` likewise require `(Discovery.Activity is Loggable)^` in scope,
  which `anticipation.Loggable.fanOut` derives from the `Communicable` with no further import
  (silent with no `LogSink` in scope), so call sites compile unchanged; a `Backend`
  implementation must add the parameters. (#2186)
