# Changes since 0.71.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.71.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## acyclicity

- `acyclicity.Dag#++(dag: Dag[node]): Dag[node]` (`@targetName("addAll")`) removed. Replaced by
  the given `acyclicity.Dag.concatenable: [node] => Dag[node] is Concatenable by Dag[node] to
  Dag[node]`, so `left ++ right` now resolves through `symbolism.++` (in scope via
  `import symbolism.*` or `import soundness.*`). Semantics unchanged. (#PR)

## anticipation

- `anticipation.Text.addableString: [text <: Text] => text is Addable by String to Text` renamed
  to `anticipation.Text.concatenableString: [text <: Text] => text is Concatenable by String to
  Text`. `text + "string"` becomes `text ++ "string"`. (#PR)
- `Text` is no longer `Addable`: `text + text` no longer compiles; write `text ++ text`
  (`anticipation.Text.concatenable` is unchanged, and `symbolism.++` is new, see symbolism). The
  previous behaviour is restored in a scope by `import symbolism.arithmeticOptions
  .concatenativeAddition` (also `soundness.arithmeticOptions.concatenativeAddition`). (#PR)

## build

- The tools in `etc/tools` are flair 0.6.0 (the compiler plugin Soundness is compiled with),
  fume 0.7.0 (the test runner) and flame 0.6.0, each built against Soundness 0.71.0 and
  Pyrocosm 0.6.0 (were flair 0.5.0, fume 0.6.0 and flame 0.5.0). No library's API changes.
- `etc/xek.tsv` pins xek 1.3.0 (was 1.2.0), and `etc/ci/xek-fetch.sh` fetches only releases
  tagged with the bare version, from 1.0.0; a pin naming an `xek-0.x` or `xeq-0.x` builder no
  longer resolves. The build fetches the builder safely when several test modules resolve it
  at once on a cold cache, which failed when they shared one temporary file. No library's API
  changes.

## cataclysm

  Css is Concatenable by Css to Css`; `css + css` becomes `css ++ css`. (#PR)
- `cataclysm.Css.Style.addable: Style is Addable by Style to Style` replaced by
  `cataclysm.Css.Style.concatenable: Style is Concatenable by Style to Style`; `style + style`
  becomes `style ++ style`. (#PR)
- `cataclysm.Css.Errors#+(error: Css.Error): Css.Errors` removed. Replaced by the given
  `cataclysm.Css.Errors.appendable: Css.Errors is Appendable by Css.Error`; `errors + error`
  becomes `errors :+ error` (`rudiments.:+`). (#PR)

## charisma

- `charisma.Formulable#+(formulable: Formulable): Chemical.Formula` (`@targetName("plus")`)
  removed. Replaced by the given `charisma.Formulable.addable: [left <: Formulable, right <:
  Formulable] => left is Addable by right to Chemical.Formula`, so `left + right` resolves
  through `symbolism.+` (in scope via `import symbolism.*` or `import soundness.*`). Semantics
  unchanged. (#PR)

## concordance

- `rudiments.:+` was `extension [self, operand](value: self)(using appendable: self is
  Appendable by operand) infix def :+ (element: operand): self`; it is now `extension [self]
  (value: self) infix def :+ [operand](element: operand)(using appendable: (self is Appendable)
  { type Operand >: operand }): self`. The operand is fixed by the element rather than by the
  instance, and an instance may declare a wider operand than the element. Consequence: in a
  scope importing `rudiments.*` or `soundness.*`, a stdlib `scala.IArray` or `scala.Array` `:+`
  (which is an extension, not a member) now resolves to this operator and fails for want of an
  `Appendable` instance; write `appended(element)` instead. (#PR)

## contingency

- `contingency.Validation#+(pointer: Pointer, message: Message): Validation` removed. Replaced by
  the given `contingency.Validation.appendable: Validation is Appendable by (Pointer, Message)`;
  `validation + (pointer, message)` becomes `validation :+ (pointer, message)`. (#PR)

## gossamer

- `gossamer.Dictionary#+[value2 >: value: ClassTag](entry: (Text, value2)): Dictionary[value2]`
  removed. Replaced by the given `gossamer.Dictionary.appendable: [value: ClassTag] =>
  Dictionary[value] is Appendable by (Text, value)`; `dictionary + entry` becomes `dictionary :+
  entry`. The result has the dictionary's own value type: to widen it, use `Dictionary#add(key:
  Text, value: value2): Dictionary[value2]`, which is unchanged. (#PR)
- `gossamer.Dictionary#++[value2 >: value: ClassTag](extras: Iterable[(Text, value2)]):
  Dictionary[value2]` removed. Replaced by the given `gossamer.Dictionary.concatenable: [value,
  value2 >: value: ClassTag, extras <: Iterable[(Text, value2)]] => Dictionary[value] is
  Concatenable by extras to Dictionary[value2]`; `dictionary ++ extras` is unchanged at the call
  site but resolves through `symbolism.++`. (#PR)

## serpentine

- `serpentine.Path#+(relative: Relative): Path` (transparent inline; result `Path[Plane, Limit,
  Tuple.Concat[relative.Topic, Tuple.Reverse[Tuple.Take[Tuple.Reverse[Topic], relative.Limit]]]]`)
  removed; `path + relative` becomes `path ++ relative` (`symbolism.++`). Replaced by two givens:
  `serpentine.Path.concatenable: [plane, limit, topic <: Tuple, path <: Path of topic on plane
  under limit, ascent <: Int, descent <: Tuple, relative <: Relative of descent under ascent] =>
  path is Concatenable by relative to (Path of Tuple.Concat[descent, Tuple.Reverse[Tuple.Take[
  Tuple.Reverse[topic], ascent]]] on plane under limit)`, which applies when both operands'
  topics are statically known and types the result as before; and the lower-priority
  `serpentine.PathUntyped#concatenableUntyped: [plane, path <: Path on plane, relative <:
  Relative] => path is Concatenable by relative to (Path on plane)` (inherited by `object
  Path`), which applies otherwise and types the result as a bare `Path on plane`, where the
  member previously kept `Limit`. (#PR)

## stratiform

- `stratiform.Revision#++(next: Revision): Revision` removed. Replaced by the given
  `stratiform.Revision.concatenable: Revision is Concatenable by Revision to Revision`;
  `revision ++ revision` now resolves through `symbolism.++`. (#PR)

## symbolism

- New operator `symbolism.++`: `extension [left](left: left) inline infix def ++ [right](right:
  right)(using concatenable: left is Concatenable by right): concatenable.Result`, exported as
  `soundness.++`. Consequence: in a scope importing `symbolism.*` or `soundness.*`, a stdlib
  `scala.IArray` or `scala.Array` `++` (an extension, not a member) now resolves to this operator
  and fails for want of a `Concatenable` instance; write `scala.IArray.concat(left, right)`,
  `left.appendedAll(right)`, or join the opaque `Array[element]^{}` values with `++` (through
  `symbolism.Concatenable.frozenArray`). (#PR)
- `symbolism.Addable.concatenable: [left, right] => (concatenable: left is Concatenable by right)
  => left is Addable by right to concatenable.Result` removed. The same given is now
  `symbolism.arithmeticOptions.concatenativeAddition` (mirrored as `soundness.arithmeticOptions
  .concatenativeAddition`), imported by name. Consequence: `+` between values whose only instance
  is `Concatenable` — `Text`, `List`, `Sequence`, `Chain`, `Set`, `Map`, `Ledger`, frozen
  `Array`, `Teletype`, `Writing`, `Ascii`, any `Textual`, `Css`, `Css.Style`, `Html`,
  `ClassList`, `Query`, `Message` — no longer compiles; write `++`, or import the given.
  `rudiments.total` over such values (it requires `Addable`) likewise no longer resolves; use
  `join`. (#PR)
- `symbolism.Multiplicable.concatenable` is unchanged in type; it repeats through
  `Concatenable#concat` rather than `+`. (#PR)

## syndesis

- `syndesis.Discovery.Backend#advertise(service: Discovery.Service, description:
  Discovery.Description)(using Monitor^, Probate^, Tactic[Discovery.Error])` now returns
  `Discovery.Advertising` (new trait, one member `def instance: Discovery.Instance`) instead of
  `Discovery.Instance`, and `Discovery.Backend#withdraw` takes `(advertising:
  Discovery.Advertising)(using Monitor^)` instead of `(instance: Discovery.Instance)(using
  Monitor^)`. A `Backend` implementation must return a handle and accept it back; a caller using
  the seam directly reads the name as `advertising.instance`. The loan
  `service.advertise(description) { … }` is unchanged. (#2186)
- `syndesis.Discovery.Advertisement`'s constructor takes `(advertising: Discovery.Advertising)`
  instead of `(val instance: Discovery.Instance)`; `instance` is now a `def` that reads the
  backend's current name. Its value may change during the block: after RFC 6762 §9 re-probing,
  `Mdns.Responder` renames an established instance (`Gondor` → `Gondor (2)`) when another host
  is found to hold its name, where previously such a response was only cached. Code that reads
  `instance` once and reuses it must re-read it when the name matters. (#2186)
- `syndesis.Mdns.Transport` replaces `def receive(): Packet raises Socket.Error` with `def
  inlets: List[Mdns.Transport.Inlet]`, where `Mdns.Transport.Inlet` (new trait) has `def
  receive(): Packet raises Socket.Error`; `Mdns.Transport.sockets` now joins `ff02::fb` as well
  as `224.0.0.251` (one inlet each) on interfaces with an address of that family, and fails only
  if neither group can be joined. A `Transport` implementation with one socket extends `Inlet` too and
  returns `List(this)`. `Mdns.Transport.Bus#join` now returns `Transport & Transport.Inlet`
  (previously `Transport`), so `receive()` on a bus member is unchanged. (#2186)
- `syndesis.Discovery.Backend#advertise`, `#browse` and `#resolve` take an additional using
  parameter `(Discovery.Activity is Loggable)^` in their final `using` clause (after
  `Tactic[Discovery.Error]`), and `#withdraw` takes `(using Monitor^, (Discovery.Activity is
  Loggable)^)` instead of `(using Monitor^)`; `Discovery.Activity` is a new enum (`Probing`,
  `Yielded`, `Conflicted`, `Claimed`, `Withdrawn`, `Browsing`, `Resolved`) with a `Communicable`
  given. The loans `service.advertise(description) { … }`, `service.browse { … }` and
  `instance.resolve(timeout)` likewise require `(Discovery.Activity is Loggable)^` in scope,
  which `anticipation.Loggable.fanOut` derives from the `Communicable` with no further import
  (silent with no `LogSink` in scope), so call sites compile unchanged; a `Backend`
  implementation must add the parameters. (#2186)

  `Cookie.Value.encodable`, so the header is named `Set-Cookie` where it was `set-cookie`. (#PR)
