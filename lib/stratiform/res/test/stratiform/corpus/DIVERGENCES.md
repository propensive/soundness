# Corpus divergences from the Rust reference implementation

The fixtures were ported from the Rust reference implementation at the commit
recorded in `UPSTREAM_SHA`, and `.check` files were originally generated by that
binary. `etc/sync-tel-corpus.sh` re-syncs them; the fixtures it lists as
`LOCAL_ONLY` are local additions with hand-written `.check` files, covering
pragma forms (the LIRA reference grammar's bare, tag and version selectors,
layers with signatures, the pinned `tels` coordinate) and E121/E122 cases the
upstream corpus does not exercise. A sync never deletes them. `tels.tel` and
`tels.bintel.hex` are maintained by hand and match upstream.

## Pattern constraints (§21.8)

Pattern matching is backed by `praxinoscope`, which implements RE2 syntax
including inline flags (`i`, `m`, `s`, `U`, in both the `(?flags)` and
`(?flags:…)` forms), POSIX classes (`[[:alpha:]]`), Unicode general categories
and scripts (`\p{Lu}`, `\pL`, `\p{Greek}`, and their `\P` complements),
quoted runs (`\Q…\E`), and named capturing groups.

One divergence remains, and it is in the *containment* analysis rather than in
matching:

- **Word boundaries** (`\b`, `\B`) and, under the `m` flag, the line anchors
  `^` and `$` parse and match correctly, but the containment analysis cannot
  model them (`Unverifiable`) because they depend on the symbols surrounding a
  position rather than on the position alone. A layer replacement involving one
  is therefore not provable and fails closed as **E223**. Matching such a
  pattern against a value is unaffected.

(An earlier revision of this file claimed `\Z` was an unsupported gap. That was
wrong: RE2 has no `\Z` — it spells end-of-text `\z` — so rejecting it is
correct behaviour, not a divergence.)

The §21.8 resource budget this implementation documents is
`praxinoscope.Subsumption.maxStates` = 100,000 product states, matching the Rust
reference's `STATE_BUDGET`. Exhausting it is reported as E223, per §21.8's
requirement that a budget exhaustion be treated as *not proven*.

## Presentation model: a blank line opening a child block

`pos/blank-before-first-child` and `pos/blank-before-deeper-comment` (from
upstream 206686c, "a blank line opens a child block") parse to the same
structure here, but the reference's dump has no place for the blank line
itself: `Block.trailing_blank_lines` counts blank lines *after* a block, and
nothing precedes the first child block, so the reference discards the line and
its output cannot reproduce the source. This implementation represents it as a
leading blank-only `Block` (no comments, no compounds, `trailing_blank_lines`
= the run length), which prints back byte-for-byte; the round-trip tests in
`stratiform_test` pin that. The two fixtures are exempted from the tree
comparison for this reason (`treeDivergences` in `stratiform_test`).

## Diagnostics

`e119-non-space-after-marker`: this implementation reports one E119 per
malformed heading, where the reference reports one per marker. The accrual
tests exempt the fixture from their strict comparison for that reason.
