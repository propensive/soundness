# `↯/s.105.9` — `Certificate.Path.Error`

Raised when a chain of certificates does not lead to a trusted one.

## Cause

`Certificate.validate` takes a chain — the certificate being relied on, then the certificate
of each authority that issued the one before — and a set of trusted anchors. Each certificate
must be within its validity period, name the next as its issuer and be signed by it; every
issuer must be a certificate authority; and the last must be an anchor, or be issued by one.

## Variants

```tabular
column  Code
column  Reason
column  Message
row  `↯/s.105.9.1`  `Empty`  it holds no certificate
row  `↯/s.105.9.2`  `Malformed`  a certificate in it is not well-formed
row  `↯/s.105.9.3`  `Expired`  a certificate in it is outside its validity period
row  `↯/s.105.9.4`  `BadSignature`  a certificate in it was not signed by the next
row  `↯/s.105.9.5`  `Unlinked`  a certificate in it was not issued by the next
row  `↯/s.105.9.6`  `NotAuthority`  a certificate in it was issued by one that is not an authority
row  `↯/s.105.9.7`  `Untrusted`  it does not lead to a trusted certificate
```

## Resolution

`Untrusted` means the chain is sound as far as it goes but ends somewhere that is not among
the anchors: an intermediate certificate is missing from the chain, or the right root is
missing from the anchors. `Unlinked` usually means the chain is in the wrong order; it runs
from the leaf towards the root. `Expired` is judged by the `Clock` in scope.

Revocation, name constraints, policies and path-length limits are not examined, so this
validation suits a closed set of anchors chosen for one purpose, not the public web's.
