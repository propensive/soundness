# Changes since 0.78.0

This file is read by an LLM agent to upgrade code that consumes Soundness libraries from
0.78.0 to the next release. Each entry states precisely what changed; see `AGENTS.md` for the
format. Entries are grouped by module, most-recently-added last within a module.

## delicious

- `enum delicious.Markup` has two new cases, `Tree(omitted: Int, children: List[Markup])` and
  `Node(role: Markup.Role, name: Text, note: Optional[Text], repeated: Boolean, children:
  List[Markup])`. A `match` on a `Markup` which names every case must name these two.
  (#2547)
- `delicious.Markup.parse` returns `Markup.Tree` for a marker of kind `tree`, and `Markup.Node`
  for a marker of kind `node` whose `role` attribute is one of `resolving`, `candidate`,
  `requires`, `propose`, `prohibits` or `found`; it previously returned `Markup.Spanned(t"tree",
  …)` and `Markup.Spanned(t"node", …)`. A `node` marker with any other `role`, or with none, is
  still a `Markup.Spanned`. `Markup#plain` of either new case is the concatenated `plain` of its
  children, as it was for the `Spanned`. (#2547)

## frontier

- When the compiler option `-Zsemantic-diagnostics` is set, the error message reported by
  `frontier.context.explainMissingContext` and by `soundness.explainMissingContext` is the result
  of the new `frontier.Diagnostic.markup` instead of `frontier.Diagnostic.render`: the same text
  with no ANSI escapes, with a `tree` marker around the tree and a `node` marker around each
  node's line and the lines of its children, in the marker format `delicious.Markup.parse` reads.
  `delicious.Markup.plain` of the message is the text of `Diagnostic.render` with its ANSI
  escapes removed. Without the option the message is unchanged. Code which searched such a
  message for ANSI escapes, or split it into lines without first stripping the markers, must
  parse it with `delicious.SemanticMessage.parse` and read `SemanticMessage#trees`, or strip it
  with `delicious.Markup.plain`. (#2547)
- The `frontier-core` artifact now depends on `delicious-core`. (#2547)
